Harness for Robotics

Harness 指包在模型外面（或模型内部）的那层执行框架：每一步让模型看到什么、跨步记住什么、任务怎么拆、拆完以什么接口交给下一层、执行时用什么信号判断对错、判断之后改什么。本专题按这个视角读机器人基础模型的论文。

本页按五类收录 15 篇：（1）总体设计（ASPIRE、PyRUA-Lean）、（2）上下文架构（ActiveVLA、TIC-VLA、RA-VLA）、（3）持久状态与记忆（MemoryVLA、OptimusVLA、SOMA、HiMe）、（4）结构化执行（ACoT-VLA、MotorMind）、（5）评估与反馈（TT-VLA、τ₀-WM、RoboTTT、τ₀-VLA）。每篇有单独的精读页，下面是五类的定义、各篇的位置、索引和横向对照。

五类 harness

分类按专题定义，每篇归入一类，归类取它们的主要贡献。有几篇跨类：SOMA 的记忆要靠一次主动扫描才建得起来，和（2）的「看哪里」耦合；OptimusVLA 的全局记忆其实是跨回合的轨迹检索，机制上接近 RA-VLA；τ₀-VLA 与 MotorMind 都带执行记忆，也沾（3）；RoboTTT 的快权重本身就是跨步的状态，测试时的更新信号是自监督的，显式评价只出现在训练时，同样贴着（3）。

（1）

总体设计 Overall Design

把整套 harness 当作一个系统来设计：智能体用什么接口驱动机器人、观测和执行结果怎样回到模型、经验怎样沉淀复用。这一类论文不只改其中一环，（2）–（5）的几个问题在同一个循环里一起回答，比较的对象也是另一套完整的 harness。

  • ASPIRE：跨任务的经验沉淀。按任务写机器人程序，执行引擎记录逐原语的多模态 trace，调试加进化搜索修程序；复现过的修复写进技能库，后面的任务当上下文读。
  • PyRUA-Lean：回合内的交互接口。机器人暴露成一个 Python 对象，模型每次写一段代码组合原语（VLA 也是原语），自己决定回传哪些图像和状态；同一规划器、同一套原语下和工具调用对比。
（2）

上下文架构 Context Architecture

设计模型每次决策时看到什么、以什么形式看到，包括检索、视觉选择、时序对齐等。

  • ActiveVLA：视觉选择。在已重建的点云上挑虚拟视点、放大，决定 VLM 看哪几张图。
  • TIC-VLA：时序对齐。慢 VLM 的结果带着「多旧了、期间走了多远」交给快控制器。
  • RA-VLA：检索。按动作阶段从新任务示范里取片段，喂进动作头。
（3）

持久状态与记忆 Persistent State / Memory

在多步任务中持续保存任务状态、空间状态和执行历史，使当前动作不只依赖于当前 observation。

  • MemoryVLA：执行历史。VLM 与动作头之间按时间累积的特征记忆库。
  • OptimusVLA：执行历史与跨回合先验。检索来的轨迹和已执行的动作块都接在去噪起点上。
  • SOMA：空间状态。视野外的物体写成带 3D 框的物体 token。
  • HiMe：任务状态。策略之外的图文记忆和子任务计划表，由大模型增改删。
（4）

结构化执行 Structured Execution

把复杂任务组织为「推理 → 意图/子任务 → 动作」的分层受控执行流程，通过明确的中间接口连接高层决策与低层控制。

  • ACoT-VLA：接口在模型内部，是一段动作空间里的粗参考轨迹。
  • MotorMind：接口全在模型外部，是带成功判据的子目标和带数值的中层动作 JSON。
（5）

评估与反馈 Evaluation & Feedback

在执行前或执行后引入显式评价信号，根据结果修正计划、更新状态或适应策略，形成闭环。

  • TT-VLA：执行后，用进度估计的差分做奖励，在回合内更新策略参数。
  • τ₀-WM：执行前，在动作块层面。策略先给出 4 个候选，用重去噪一致性筛选；不可靠时由同一视频主干的模拟器想象每个候选的未来并打进度分，再朝最好的未来重新生成。
  • RoboTTT：执行后，每一步的观测和动作都写进动作头的快权重；训练时用人的纠正（DAgger Distillation）教它怎样根据失败调整。
  • τ₀-VLA：执行前，用世界模型想象候选子任务的后果、价值模型打分，再提交。

2026-06arXiv 2607.00272
NVIDIA GEAR、UMich、UIUC、UC Berkeley、CMU
总体设计

ASPIRE

Agentic /Skills Discovery for Robotics

做法
Coordinator 按课程给每个任务派一个编码智能体（Claude Code / Codex）。它在 15 个调试种子上反复「写 Python 机器人程序 → 执行 → 读逐原语轨迹（调用、返回值、前后关键帧）→ 修复」，陷入局部时用进化搜索每轮提 K 个候选程序。另起一个 verifier 只凭技能描述把源任务重新做成，这条修复才进技能库，后面的任务当上下文读。LIBERO-Pro 和 Robosuite 上每个任务交出一份程序，在 held-out 种子上跑一次，评测时不调大模型。
结果
Claude Opus 4.6 时 LIBERO-Pro 三套件、两种扰动平均 72%（CaP-Agent0 18%，π0.5 13%），Robosuite 7 个任务 81%（68%），BEHAVIOR-1K 两个任务都是 88%；LIBERO-90 攒的技能库零样本用到 LIBERO-Pro Long 30.5%（3.8%）。换 Opus 5.5 后 80 个任务 99.2%。消融：无执行引擎 14% → 加引擎 62% → 加进化搜索 72%。
疑点
主结果协议不对等：ASPIRE 先在同一个扰动任务的调试种子上反复执行、改程序再评测，VLA 没见过扰动任务，CaP-Agent0 每个种子临场生成。「加执行引擎」一级同时加了多轮执行、轨迹和技能库，轨迹粒度本身没单独测。同一模型、同一任务，不同运行可以从 0% 到 100%，各表都是单次运行。

北大、NUS、NVIDIA、Impossible Research
总体设计

PyRUA-Lean

Fewer Tokens, Better Action: GPT-6 Astra Robot Agents with 14% Higher Success Rate but 65% Fewer Tokens

做法
Harness VLA（文中称 RPent）的原语原样保留，改由一个 robo 对象暴露；GPT-6 Astra 只通过 python(code) 写 cell，在 cell 里串原语（冻结的 π0.5、LingBot-VLA、RLDX-1 也是原语）、检查结果、就地重试，变量在回合内保留，只有 print 的内容和点名要的图回到上下文。没有跨回合记忆。v2 另加两部分：RoboDojo 上作者手写几何原语、不用 VLA 的版本；在 45 个 LIBERO-PRO 实例上用 GRPO 训练的 Qwen3.5-4B 规划器。
结果

钱花在开发期，还是每个回合？

ASPIRE 不开进化搜索时每个任务花 $10.8（Opus 5.5）到 $32.1（Opus 5），交出的程序在 50 个评测种子上不再调大模型。PyRUA-Lean 每个回合都要付，LIBERO-PRO 上两边都成功的回合，代码 $0.79、工具调用 $2.49。前者要求部署前能在同样的环境里反复执行、自动判成败（仿真，或能重置的真机）；后者每回合都要大模型在环，两篇都没有报告每步延迟。

观测让模型自己挑，但只少给图不够

PyRUA-Lean 的 cell 自己决定 print 什么、要哪张图；ASPIRE 的执行引擎把逐原语轨迹存下来，由智能体挑着读。PyRUA-Lean 有一个对照：工具调用改成按需取图后，LIBERO-PRO 成功率 83.0% → 68.5%，三种配置都成功的实例上 token 和原来差不多。少给图要和「把多步操作留在运行时里」一起才省。ASPIRE 的消融把执行引擎整体加进来（14% → 62%），轨迹给多细没有单独测。

三篇的 LIBERO-PRO 数字不能放在一起比

ASPIRE 的 72%（Opus 4.6）和 99.2%（Opus 5.5），是每个任务先在调试种子上反复执行、改程序，再用一份程序评 50 个种子。PyRUA-Lean 的 94.0% 是每回合现做，冻结 π0.5 当原语、能读成功标志。MotorMind 扰动 53.8% 也是每回合现做，但不用 VLA、不读成功标志。同一个 Harness VLA，在 MotorMind 里用 Qwen 规划器扰动设定 28.8%，在 PyRUA-Lean 里换成 GPT-6 Astra 是 83.0%。规划器和套件都变了，只能说明这类 harness 的数字对规划器非常敏感。

完成判定，两篇的主实验都交给了仿真器

下面「跨类的线索」第一条说「子任务做完没有」是共同的薄弱点。ASPIRE 调试时的分数来自仿真器在调试种子上的成功判定；PyRUA-Lean 的对比实验里两个智能体都能读基准的成功标志，代码的重试和截停都靠它。要自己从图像判完成的，只有 PyRUA-Lean 的 RoboDojo 一节（51.6%）和 MotorMind（扰动设定下 9% 的回合错误宣布完成）。

看不见的东西：换个视角，还是记下来？

ActiveVLA 在已经重建的点云上重渲染虚拟视点，物理相机不动，能看到的上限是已经拍到的点；SOMA 真的转动头部相机扫一圈，把视野外的物体写进记忆。前者每个关键帧重新选、不留状态；后者扫描一次、之后靠门控刷新，代价是被挪走的物体会留下陈旧条目（论文承认，没有实验）。

记忆存成什么？

MemoryVLA 存特征 token，按时间排、满了合并；OptimusVLA 存动作，一边是跨回合的轨迹库，一边是本回合已执行的动作块；SOMA 存物体 token，按物体索引、不带时间戳；HiMe 存人可读的图文记录，由大模型增改删。前三篇的记忆在策略的一次前向里被读，HiMe 的记忆只经一句子目标进入 π0.5。

记忆本身贡献多少，证据不齐

MemoryVLA 没有「同一套训练、只去掉记忆」的对照，只能和复测的 CogACT 比；SOMA 在 GR1 上的消融增益几乎全来自「容器交互」一类；OptimusVLA 去掉 GPM / LCM 后 LIBERO-Long 从 96.4 降到 93.2 / 94.8；HiMe 在同一层级骨架下比了无记忆（14）和 FIFO 式记忆（65），对 90，四篇里最直接。

加上 harness 的代价

ActiveVLA 每次推理约翻倍（RLBench 0.26 → 0.53 s）；SOMA 每个动作块 1.30 → 1.58 s；MemoryVLA 0.187 → 0.194 s；OptimusVLA 反而更快（57 → 39 ms），因为去噪步数从 10 降到 3.2；HiMe 的 GPT-4o 单次调用中位 38.59 s，整任务耗时没有报告。各篇计时口径不同，只能各自和自己的基线比。

跨类的线索解读

（2）（3）的七篇和（4）（5）的六篇放在一起看。

「子任务做完没有」是共同的薄弱点

HiMe 的 Sentry 判完成，精确率约 82%、召回约 35%（正文数字，对应原文图 7）；MotorMind 的诊断里六个通用 VLM 判完成只有 47.5–82.5%（二分类），扰动设定下 9% 的回合错误宣布完成；τ₀-VLA 不测判别器，而是用记忆滞后、超前、未察觉失败三类扰动样本训练纠错。下面「评价器本身可靠吗」一条说（4）（5）三篇都没评估评价器，HiMe 是在自己任务上量过的一篇。

异步分层里，只有 TIC-VLA 告诉低层上下文有多旧

τ₀-VLA 的低层读约每 1 s 刷新的子任务缓存，搜索没算完时按旧子任务执行；HiMe 等 GPT-4o 的那几十秒里机器人怎么办没有写；MotorMind 主线串行。TIC-VLA 的「同一个 KV 接口，不建模延迟 30.59、建模后 47.06」是 11 篇里唯一直接说明延迟要显式建模的对照。

给动作头一段动作先验，怎么逼它读？

RA-VLA 读别人同一动作阶段的动作块，并用它们的均值当去噪起点；OptimusVLA 用检索到的训练集轨迹当起点；ACoT-VLA 读自己的 EAR 生成的 15 点粗轨迹。逼动作头读的办法分别是 margin 损失（去掉后 LIBERO-Goal 0.532 → 0.098）、只在推理时换起点（flow 只在高斯起点上训练过）、teacher forcing。ACoT-VLA 和 OptimusVLA 用同一个 π0.5 基线（LIBERO 96.9，Long 92.4），提升都集中在 Long。

「测试时适应」至少有四种意思

RA-VLA 不改权重，往库里放新任务的几条示范，每个动作块检索一次；TT-VLA 在回合内每 8 步更新一次 LoRA，下个回合重置；τ₀-VLA 把测试时的算力花在子任务搜索上；RoboTTT 每一步都更新动作头里的快权重，但这个更新规则在训练时就已经元学习好，不需要外部评价器。RoboTTT 的相关工作把 TT-VLA 归为「在测试任务上收集数据微调整个模型」，与 TT-VLA 的实际做法不符。TT-VLA 只适用于离散 token 的自回归 VLA，（2）（3）类七篇的动作头都不在它的适用范围内。

（4）（5）里的线索解读

语言子任务够不够细？

ACoT 和 MotorMind 都认为「子任务文本 → 动作」这一跳太大，一个在模型里多生成一段动作草稿，一个让 VLM 直接说出带数值的动作。τ₀ 仍用语言子任务，但它处理的是分钟级任务，问题不在接口粒度，而在选哪个子任务。三者处理的是不同时间尺度，可以叠加。

评价器本身可靠吗？

MotorMind 的诊断里，通用 VLM 判断进度的准确率只有 43–76%，扰动设定下还有 9% 的回合「宣布完成但其实没完成」。TT-VLA 的奖励完全来自 VLAC 的进度估计，τ₀ 的打分完全基于世界模型的想象。三篇都没有直接评估评价器在自己任务上的准确率。RoboTTT 绕开了这个问题：测试时不需要评价器，评价（人的纠正）只在训练时出现。

执行前，还是执行后？

τ₀-VLA 和 τ₀-WM 在承诺前评价，代价是要训练世界模型、只能评价想象；TT-VLA 和 MotorMind 在承诺后评价，代价是错误已经改变了环境。τ₀-VLA 的引言把这一点说得很直接：重规划可以响应，但收不回失败承诺的代价。两篇出自同一团队，一个在子任务层想象终态图，一个在动作块层想象视频与逐帧进度，彼此没有引用；τ₀-VLA 认为动作层的搜索只看得到局部后果，τ₀-WM 正处在那一层。

统计强度普遍偏弱

六篇的真机实验每格 10–40 次（τ₀-WM 主结果未披露），仿真里 TT-VLA 每格 240 次但增益只有 1–4 个点。都没有报告方差或显著性检验。读结论时，看试验次数比看百分比更重要。
