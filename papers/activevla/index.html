ActiveVLA

Injecting Active Perception into Vision-Language-Action Models for Precise 3D Robotic Manipulation

相机其实一台都没动。ActiveVLA 把标定相机的 RGB-D 拼成点云，先让 PaliGemma 在三张正交投影图上找出关键 3D 点，再在以它为球心的测地球面上挑 3 个虚拟视点，对最好的那个把视场角缩小 4 倍重新渲染，用这些图预测下一个关键帧位姿。它改的是 VLM 每一步看到的图像：从哪个角度渲染，放大多少倍。

做了什么

沿用 BridgeVLA 的 PaliGemma 骨干和"2D 热图 → 3D 平移"框架，做两遍：粗阶段看三张正交投影找关键点 pf；精阶段改看主动挑选的透视虚拟视图。挑法是球面候选按可见性、距离、多样性的 Z 分数加权取 top-3，再对最佳视图做 FoV/z 的 3D zoom-in（z = 4）。这两步是几何计算，没有可学习参数。

设置

RLBench 18 个任务（每任务 100 条示范）、COLOSSEUM（附录列 20 个任务 × 12 类扰动）、GemBench（16 个训练任务 / 44 个测试任务），每个基准各训一遍；真机 4 个强遮挡任务。仿真只比关键帧式 3D 策略和少量 2D 基线。

结果

RLBench 平均 91.8（BridgeVLA 88.2），COLOSSEUM 65.9（64.0），GemBench 51.3（50.0）。自家消融里两个模块合计 +4.2 / +2.3 / +2.4 个百分点，推理时间约翻倍（表 4：RLBench 0.26 → 0.53 s）。真机 4 任务平均 91.8，最强基线 RVT-2 72.5。

最该留意的

"主动"发生在渲染空间，只能重新摆放已经观测到的点。按正文公式，完整测地球面上距离项和多样性项对每个候选都是同一个常数，排序只剩二值的可见性。真机平台、COLOSSEUM 分项、真机总成功率，在正文和附录里各有两套说法。

问题 · §1、§3

固定相机被挡住、看不清，就换个角度、凑近看

论文的任务设定沿用 PerAct / RVT 一系：策略 π 把观测 o 和指令 l 映射到下一个关键帧的动作 a，包括末端 6-DoF 位姿 T ∈ SE(3)、夹爪开合 g ∈ {0, 1} 和一个碰撞标志 c ∈ {0, 1}，关键帧之间交给运动规划去走。观测 o 是一台或几台固定相机（或腕部相机）拍的 RGB-D。

作者认为问题出在这些相机的视点和分辨率是死的：目标被别的物体挡住时换不了角度，目标太小时拉不近。长时程和精细操作都会因此丢掉关键信息。开篇引了 Richard Gregory 的一句话："感知不是被动的过程，而是主动检验假设的过程。"

它的回答分两步：先粗略确定"该看哪儿"，再决定"从哪看、看多近"。后一步对应两个模块，主动视角选择（A-VS）和主动 3D 放大（A-3Z）。

解读示意图和方法之间隔着一层"渲染"

图 1 上排用三张从不同物理位置拍的真实照片表现"换个角度看"。但方法里的新视角是对已有点云的重渲染（§3.2 原文："re-renders the scene"、"virtual rendering space"），实际样子见下文图 3 的点云渲染图。虚拟相机能绕开"渲染时的前景遮挡"，前提是被挡住的那部分曾经被某台物理相机拍到过；任何一台相机都没拍到的地方，换多少个虚拟视点也是空的。

解读和前作的关系

把点云渲染成正交视图再喂给模型，是 RVT / RVT-2 的做法（论文引了它们）；骨干和热图框架直接取自 BridgeVLA（§4 "adopts the pre-trained VLM backbone from BridgeVLA"）。RVT-2 本身已有"先粗定位、再围绕该区域放大重渲染"的两阶段设计。ActiveVLA 的新意落在精阶段：视点不再是固定的正交方向，而是围绕关键点在球面上挑；放大改用透视相机缩视场角。论文没有和"固定方向放大"单独做对照。

§3.1–3.3 · 附录 C

    解读可学习的部分只有两处

    粗阶段的热图决定关键点 pf（学的），精阶段的热图和 MLP 头决定动作（学的）。中间"从哪看、看多近"由固定公式算出，梯度不经过它。所以 ActiveVLA 的"主动"是：学到的注意力（热图）告诉几何模块往哪儿凑，几何模块按手写规则决定怎么凑。

    方法 · 粗阶段 · §3.1

    三张正交图 + 热图，先找出"该看哪儿"

    多视图渲染。用标定相机的 RGB-D 重建场景点云，从顶、前、右三个方向做正交投影。每个视图渲染 7 个通道：RGB 3 个、深度 1 个、点的世界坐标 3 个。世界坐标通道的作用是建立跨视图的像素对应：不同视图里 (x, y, z) 相同的像素就是同一个 3D 点。渲染用 PyTorch3D，每个像素取深度最小的点，保证遮挡正确：

    I(v)(ux, uy) = Σi=1..N ci · δ( (ux, uy) − π(v)(pi) )，  π(v) 为正交投影(2)

    关键区域提取。三张图连同指令进 VLM。作者认为 VLM 的全局表征不够做精确定位，于是把输出的 M 个 patch token 按空间位置重排成 Hp × Wp 的特征网格，用 convex upsampling（逐像素学习插值权重，而不是固定插值）放大到输入分辨率，得到热图：

    H = 𝒰( Rearrange( {ti}i=1..M ) )(3)

    热图用交叉熵训练；三个视图的热图反投影回 3D，定位关键区域，记其中心为 pf（原文举例"部分可见物体的质心"）。

    未披露粗阶段热图的监督信号是什么

    论文只说"用交叉熵训练热图"，没说粗阶段的目标是下一关键帧的末端位置，还是别的"关键区域"标注。多视图热图怎样聚合成一个 3D 点（取 argmax、加权平均还是体素投票）也没写。图像分辨率、点云裁剪范围同样没给。

    方法 · 主动视角选择 · §3.2

    围绕关键点撒一圈虚拟相机，按三项分数挑 3 个

    论文把这一步称作"假设检验式"的视角选择。给定 pf ∈ ℝ³，在以它为球心的球面上生成候选相机位置。为了各向均匀，用正二十面体递归细分做测地采样，避免经纬度网格在两极过密。论文给出细分 k 层后的顶点数：

    V(k) = 12 + 30k + (20/3)(4k − 1)(4)

    每个候选 ci 算三项分数：

    • 可见性。在 ci 到 pf 的线段上等距取 N 个点 qk，用 KD-tree 查每个点到观测点云 𝒮 的最近距离 dk。全部 dk ≥ r 则视线无遮挡，v(ci, pf) = 1，否则为 0。
    • 距离。把 ‖ci − pf‖ 归一化并在候选间标准化，"偏好适中的观察距离，兼顾视野和细节"。
    • 多样性。ci 的视线方向与所有其他候选视线方向的夹角之和。
    dk = mins∈𝒮 ‖qk − s‖，   v = 1 ⇔ dk ≥ r ∀k(5)
    Sdiv(ci) = Σj≠i arccos(vi · vj)，  𝒞 = {c1, …, cM}(6)
    si = wvis·svis + wdis·sdis + wdiv·sdiv，  wvis + wdis + wdiv = 1（三项先 Z 标准化）(7)

    取得分最高的 K 个视点作为下一次观测位姿（实验中 K = 3），每台虚拟相机用 look-at 定姿：eye = ci，target = pf，up 向量"动态调整"。得分最高的那个视点，作为下一步 3D zoom-in 的基础。

    疑点距离项和多样性项，在完整球面上都是常数

    距离：候选都在以 pf 为球心的同一个球面上，‖ci − pf‖ 全等于半径，Z 标准化的分母为 0。即便有多个半径，"偏好适中距离"也需要非线性打分；线性的 Z 分数配正权重偏远、配负权重偏近，做不到"适中"。论文没给半径，也没说用了几层球壳。

    多样性：测地球面的候选集关于球心对称。对任一候选方向 v，它的对径点贡献 π；其余候选两两成对 (u, −u)，每对贡献 arccos(v·u) + arccos(−v·u) = π。所以 Sdiv 对每个候选都等于 πM/2（M = 42 时为 65.97）。我们对 k = 0 到 3 逐一数值验证过。按字面实现，排序只剩二值的可见性，所有可见候选并列。

    就算把 𝒞 理解成"只在可见候选里求和"（演示里的第二个选项），这个分数也只奖励"离其他候选远"的单个视点，即可见区域边缘的掠射视角，不惩罚选出的 K 个视点彼此挨着。原文图 3 里选出的视角都是从斜上方看向目标，看不出退化的迹象；实际实现可能和正文公式不同（例如只在上半球采样），论文没有给出更多细节，我们无法核对。

    疑点公式 (4) 的顶点数对不上

    正二十面体按中点细分，每层把一个三角形分成 4 个，顶点数是 10·4k + 2：k = 0、1、2、3 时为 12、42、162、642。公式 (4) 给出 12、62、172、522，只在 k = 0 时对。实验用了哪一层，论文没说。

    方法 · 主动 3D 放大 · §3.2

    同一个视点，把视场角缩小 z 倍再渲染一次

    选出最佳视点后，系统在同一相机位姿下缩小视场角重新渲染，相当于在虚拟渲染空间里模拟光学变焦。设原视场角 α（弧度）、放大倍数 z > 1、相机到关注区域距离 d，渲染图在垂直视线方向覆盖的宽度为：

    W(z) = 2d · tan( α / (2z) )，   R = 图像宽度（像素）/ W(z)(8)

    W 随 z 变小，单位物理宽度分到的像素 R 随之变大。作者强调这是"利用 3D 点云做尺度不变的视图合成，没有几何损失"，并把"选视角"和"放大"概括为探索（exploration）与利用（exploitation）的分工：A-VS 管往哪儿看，A-3Z 管看多近。实验里 z 取 4。

    z论文式 W/d标准变焦 W/d相差RLBench 成功率（Figure 5b）

    W/d 按 α = 60° 计算（论文没给 α，这里只作示例）。"标准变焦"指焦距乘以 z：tan(α′/2) = tan(α/2)/z，W = 2d·tan(α/2)/z。论文式相当于把视场角本身除以 z，小角度时两者接近。

    解读放大没有增加信息，只是重新分配 VLM 的像素

    点云的密度由物理相机决定，重渲染不会凭空多出点。放大后点与点在图像上的间距随 z 同步拉大，上面演示右侧的取景框里能看到点变稀、出现缝隙。真正的收益在于：VLM 的输入分辨率是固定的（具体多少论文没说），放大把更多像素分给目标附近，热图的定位粒度跟着变细。代价是丢掉周边上下文。Figure 5b 的曲线正是这个权衡：z = 4 时 91.8 最高，z = 6 降到 90.9。

    未披露放大视图是替换还是追加

    公式 (9) 只对 3 个视图求和；K = 3 个选中视图加 1 张放大视图，到底送进 VLM 几张图，正文没说。图 2 下排画的 3 张"主动视图"里有一张明显是放大的。消融里加上 A-3Z 后单步耗时再增加 0.08–0.11 s，比只重渲染一张图要多，可能多了一张图过 VLM，但这只是推测。

    方法 · 3D 动作预测与训练 · §3.3 · 附录 C

    精阶段：热图投票出平移，全局 + 局部 token 出旋转

    主动视图和放大视图送进 VLM 生成热图。平移：把 2D 热图反投影到工作空间的离散网格 𝒢 = {g1, …, gN} 上累加成多视图得分体，取最大值处为平移目标：

    S(g) = Σv=1..3 wv · hv( πv(g) )，   t* = argmaxg∈𝒢 S(g)(9)

    旋转、夹爪、碰撞：欧拉角 (φ, θ, ψ) 每轴离散成 72 个 bin（每格 5°）。一个层次化特征融合模块汇总两类 token：

    • 全局 token：对"每个正交投影"的视觉编码器输出做 max-pool，每个视图一个，共 3 个。
    • 局部 token：用 ROI-aware sampler 抽取，编码细节外观和几何。

    全部 token 拼接后过 MLP，输出旋转、夹爪状态和碰撞标志。

    未披露精阶段还有几处没交代

    网格 𝒢 的分辨率、视图权重 wv、局部 token 的数量和采样区域、旋转与夹爪的损失形式都没给。另外，正文说全局 token 来自"每个正交投影"，可精阶段的输入是透视的主动视图；全局 token 用的是粗阶段的三张正交图，还是精阶段的主动视图，读不出来。

    附录开头说全程冻结 SigLIP 和语言 token 嵌入，言下之意 Gemma 主干参与训练；同一节末尾又说"只更新动作头、视角选择模块和 3D zoom-in 模块"。按 §3.2 的描述，后两个模块根本没有可学习参数。另外正文写"所有实验在 8 张 H100 上运行"，附录的训练用了 16 或 32 张。顺序训练的说法也让人不确定：报告 RLBench 成绩的是第一段的 checkpoint，还是后面某段的。

    读懂它

    这篇真正说明了什么

    关键 insight

    1. 改的是"VLM 看到的像素"，不是模型结构

    骨干、热图头、动作头都沿用 BridgeVLA 式设计。新东西是两个没有参数的几何模块，决定送进 VLM 的图从哪个视点、以多大视场角渲染。这是一个纯粹的上下文层改动：同一个模型，换一套取景规则，RLBench 上多 4.2 个点。

    2. 增益 2–4 个点，代价是推理时间翻倍

    A-VS +1.8 / +0.9 / +0.5，A-3Z +2.4 / +1.4 / +1.9（RLBench / COLOSSEUM / GemBench）。单步时间 0.26 → 0.53 s、0.33 → 0.62 s、0.21 → 0.59 s。按关键帧执行时每步多 0.3 s 问题不大，换成高频闭环控制就是另一回事。

    3. 视点数比视点选法更要紧

    1 个主动视图 82.2，低于 3 张固定图的 87.6；3 个主动视图 91.8。打分函数按字面又退化成只看可见性（见疑点），可以合理怀疑：增益里有多少来自"选得聪明"，有多少来自"围绕关键点、从不被挡的方向多看几眼"。论文没有"随机挑 3 个可见视点"的对照。

    4. 放大有甜点

    z = 4 最好，z = 6 回落 0.9 个点。原因是视野变窄丢上下文，再加上点云变稀。它和 RVT-2 式粗到精放大的思路一致，只是改在透视视图上做。

    容易误解的地方

    • "主动感知"不是移动相机。物理相机全程不动，所有新视角都是对已有点云的重渲染（图 1 图注：virtual cameras）。它解决不了"所有相机都没拍到"的遮挡。
    • 选视角这一步不学习。只有关键点 pf 来自学到的热图；"从哪看"由固定公式算出，权重 w 是手设的超参数（数值未披露）。
    • 动作是关键帧位姿，不是连续控制。每个关键帧完整跑一遍"粗阶段 → 选视角 → 放大 → 精阶段"；0.53 s 是每次推理的时间。
    • 不是全面领先。RLBench 的 Turn Tap 低于 3D Diffuser Actor 和 RVT-2；COLOSSEUM 的 Distractor 低于 RVT-2（54.3 vs 60.8）；GemBench 的 L1 低于 3D-LOTUS（92.4 vs 94.3），L4 远低于 3D-LOTUS++（1.2 vs 17.4）。
    • 仿真里没有和通用 VLA 比。三个仿真基准的对比对象都是关键帧式 3D 策略（RVT、BridgeVLA 等）和少量 2D 基线；真机比了 Diffusion Policy、VPP 和同团队的 TriVLA。π0、OpenVLA 一类模型都没有出现。

    FAQ

    虚拟视角到底能不能解决遮挡？

    能解决一部分。RLBench 有 4 台标定相机，融合后的点云里，目标被前景挡住常常只是因为默认渲染方向不好，换个方向渲染就能露出来，这正是可见性打分在做的事（射线检测用的是观测点云 𝒮）。但如果某块区域没有任何一台物理相机拍到，点云里就没有它，虚拟视点也看不到。真机正文只有一台固定 D455，按这个设置，换视点后目标背面应该是空洞；论文没有展示真机的虚拟视图，没法判断实际效果。

    3D zoom-in 和直接裁剪 2D 图像有什么区别？

    裁剪再缩放会插值模糊；对点云缩小视场角重渲染，每个点按原始 3D 坐标投影，不存在插值，而且能保持正确的遮挡顺序。但两者能提供的信息量都受限于原始观测：点云重渲染的代价是点间距跟着放大，图上出现缝隙（图 3 第 (d) 行）。论文说"没有几何损失"，指的是坐标精度不损失，不等于细节变多。

    和 BridgeVLA 的差别到底多大？

    同一个骨干、同一份预训练权重、同样的热图到 3D 平移框架。和 BridgeVLA 论文报告的数字比，ActiveVLA 多 3.6（RLBench）、1.9（COLOSSEUM）、1.3（GemBench）个点；和自家复现的固定视图版本比，多 4.2、2.3、2.4 个点。真机没有比较 BridgeVLA。

    多样性项为什么会是常数？

    测地球面上的候选两两关于球心对称。对任一方向 v，另一个方向 u 和它的对径方向 −u 与 v 的夹角之和恒为 π。把 M 个候选按对径配对后求和，每个候选的 Sdiv 都是 πM/2。这一项要起作用，候选集必须不对称（比如只取上半球、只取可见候选），或者改成"相对已选视点"的贪心计算。论文没说采用了哪一种。

    "假设检验"体现在哪里？

    论文把选视角称为 hypothesis testing strategy，但方法里没有显式的假设、概率或信息增益计算：每个候选算一次可见性、距离和多样性，加权排序取 top-K，一步完成，不根据看到的结果再修正。这更接近一个基于几何的启发式视点规划。

    局限与疑点

    作者承认的，和我们读出来的

    论文自己提到的

    • GemBench 最难的 L4（新长时程任务）只有 1.2%。
    • 视点数超过 3 个后成功率饱和，计算量继续增加。
    • 放大倍数过大会降低上下文感知。
    • 论文没有单独的局限性章节。

    我们读出来的

    • 疑点打分函数按字面退化：完整球面上距离项、多样性项对所有候选是常数，排序只剩二值可见性；公式 (4) 的顶点数也对不上标准细分。
    • 疑点虚拟视点的信息上限就是已观测点云。真机若只有一台 D455，视角选择能补的有限；论文没给真机的虚拟视图。
    • 疑点真机平台两套说法（Kinova + D455 eye-to-hand vs Franka + 腕部 + 两台固定相机）；照片里的机械臂外形是 Kinova。
    • 疑点真机总成功率表 5 写 91.8，正文写 96.3；每任务试验次数未披露；真机没比较最直接的基线 BridgeVLA。
    • 疑点COLOSSEUM 两套数字（表 2 vs 附录表 6），表 2 每列都更高；"与 RLBench 相同的任务"和附录任务清单不符；引言的 78.3% 是单列数字。
    • 疑点表 1 的 Turn Tap 标注错误、"10 个任务第一"、平均名次 1.22 复现不出。
    • 疑点训练描述自相矛盾：冻结 SigLIP 和词嵌入（暗示主干在训）vs "只更新动作头和两个模块"（后两者没有参数）；GPU 数 8 vs 16 / 32。
    • 试验次数口径不一：RLBench "五次试验"，表 4 "100 次试验"。
    • 精阶段输入几张图、全局 token 取自哪组视图、放大视图是替换还是追加，都没写清。
    • 放大公式用 tan(α/2z) 而非 tan(α/2)/z，不是标准的焦距变焦（差别不大，但说明式子没有仔细推导）。
    • 附录图注与图不符：图 6 说 18 个任务只画了 12 个；图 7 正文列 5 个直接操作任务，图里只有 4 个。
    • 没有"随机选 K 个可见视点"或"固定方向放大"这类对照，无法把增益归因到打分规则本身。

    放到专题里看

    "看什么"这一类里，它管的是像素层面的取景

    在 Harness for Robotics 专题里，ActiveVLA 属于 Context Architecture：它改的是模型每一步看什么，不改模型记住什么。具体形式是重渲染出来的虚拟视图，作为图像 token 进入 VLM 输入；每个关键帧从头计算，不跨步保留任何状态。同类另外两篇改的是另外两个维度：RA-VLA 往上下文里塞外部示范，TIC-VLA 处理语义上下文的时间戳。

    • 和 MemoryVLA、OptimusVLA、HiMe：点到为止。ActiveVLA 每步独立，没有记忆。这三篇分别在感知/认知 token 记忆库、检索轨迹先验加历史动作一致性、分层的文本 + 图像情节记忆上做文章，解决的是"当前观测不够、需要历史"的问题，和本篇"当前观测没看好"是两回事。
    • 和（3）结构化执行、（4）评估与反馈两类：和 ACoT-VLA 一样，都是同一个模型先粗后细跑两遍：ActiveVLA 第一遍用热图定出「看哪儿」，ACoT 第一遍用 EAR 去噪出一段 15 点的粗参考轨迹，定下「大概怎么动」；两者都串行执行，多出的时间直接算进单次推理（ActiveVLA 在 RLBench 上 0.26 → 0.53 s，ACoT 91 → 112 ms，硬件不同）。MotorMind 也是先定位再凑近：VLM 在图上画框、多个固定相机三角化，近距离换腕部相机细化；它的失败分析里，VLM 决策错误最多的一类就是定位。解读这从零样本一侧说明「看哪里、看多清」值得单独设计，但 MotorMind 用的是不训练的通用 VLM，和 ActiveVLA 微调过的热图定位不能直接比。

    术语表

    读这篇会遇到的词

    展开术语表
    active perception
    主动感知：按任务需要决定从哪里、以多大分辨率观察。本文在渲染空间里实现，物理相机不动。
    keyframe
    关键帧：PerAct / RVT 一系把轨迹压缩成少数关键位姿，策略只预测下一个关键位姿，中间由运动规划补齐。
    orthographic projection
    正交投影：平行光线投影，没有近大远小。粗阶段用顶、前、右三个方向。
    pf
    粗阶段热图反投影得到的关键 3D 点，球面候选以它为球心。
    convex upsampling
    凸上采样：每个高分辨率像素由低分辨率邻域的凸组合得到，组合权重由网络预测。
    geodesic sampling / icosphere
    测地采样：从正二十面体出发反复细分三角形并投影到球面，得到近似均匀的球面点集。
    look-at
    用相机位置（eye）、注视点（target）和上方向（up）确定相机姿态。
    Z 标准化
    减均值除以标准差。常数列的标准差为 0，标准化没有定义。
    FoV / z
    视场角 / 放大倍数。本文的放大把视场角从 α 变成 α/z，实验取 z = 4。
    A-VS / A-3Z
    Active View Selection / Active 3D Zoom-in，本文的两个主动感知模块。
    amodal
    "非模态"：指物体被遮挡部分也算在内的完整形状。论文说视角选择要"最大化 amodal 相关性"，即尽量看到目标全貌。
    BridgeVLA
    把 3D 点云渲染成 2D 图、让 VLM 输出 2D 热图再抬升到 3D 的 VLA，本文的骨干来源。
    RVT / RVT-2
    多视图虚拟渲染 + Transformer 的 3D 操作策略，RVT-2 有粗到精的放大重渲染。
    PaliGemma
    SigLIP 视觉编码器 + Gemma 语言模型组成的 VLM。
    COLOSSEUM
