MemoryVLA

Perceptual-Cognitive Memory in Vision-Language-Action Models for Robotic Manipulation

在 VLM 和扩散动作头之间加一个随时间累积的记忆库：每一步把 256 个感知 token 和 1 个认知 token 写进去；下一步用当前 token 做 cross-attention 取回相关历史，经门控和当前表示混合；库满时把相邻且最相似的两条取平均。模型只看单帧第三人称 RGB，6 个真机时序任务平均 83 分，CogACT 57 分。

做了什么

沿用 CogACT 的骨架（7B Prismatic VLM + 约 300M 的 DiT 动作头），在两者之间插入感知-认知记忆库 PCMB。工作记忆是当前帧的 256 个感知 token（SE 瓶颈压缩）加 LLaMA 在 EOS 位置输出的 1 个 4096 维认知 token。两条记忆流各存最多 L 条：仿真与真机通用任务取 16，真机时序任务取 256。

训练与评测

端到端微调，动作去噪用 MSE 损失，8 张 A100。评测覆盖 3 种机器人、6 个平台：SimplerEnv-Bridge 与 Fractal、LIBERO 五套、Mikasa-Robo，以及 Franka / WidowX 上的 12 个真机任务。所有设置都只输入一张 224×224 的第三人称 RGB，不用腕部相机和本体状态。

结果

Bridge 71.9（复测的 CogACT-Large 57.3，π0-Beta 68.4）；Fractal 72.7（CogACT 68.1）；LIBERO 96.5（CogACT 93.2）；Mikasa-Robo 41.2（π0 29.4）；真机时序任务 83（CogACT 57）。在 RTX 4090 上单次推理 0.194 s，基线是 0.187 s。

最该留意的

论文没有“同一套训练、只去掉记忆”的对照，有没有记忆只能拿 CogACT 比；而 MemoryVLA 的仿真数字取的是在测试基准上表现最好的那个验证步。消融只在 Bridge 上做，差距折合 96 次试验里的 2 到 8 次。Mikasa 一节正文说“每个任务都最好”，表里有两个任务不是。

问题 · §1–2

单帧 VLA 分不清“按过了”和“还没按”

OpenVLA、π0、CogACT 这类主流 VLA 每一步只看当前观测。论文用按按钮举例：按下前和按下后的画面几乎一样，只看当前帧没法判断这个按钮按过没有，策略就可能反复去按。操作任务是非马尔可夫的，早先做过什么会影响后面该做什么。

最直接的补法是把连续几帧一起喂给 VLM。论文认为这有两个问题：

  • 上下文长度受限。自注意力的代价随序列长度平方增长，能塞进去的帧数有限。
  • 和预训练分布不一致。VLM 的机器人预训练（Open X-Embodiment）是单帧输入，多帧序列偏离了这个分布。

相关工作里的几种时序做法，论文各点了一个短板：Octo、RoboVLMs、Interleave-VLA 用图文交错格式喂视频，实现复杂、计算贵；RoboFlamingo 把视觉语言表示压成一个 latent token 用 LSTM 传递，细粒度的感知历史基本丢了；TraceVLA 把历史轨迹画在当前帧上，丢了语义细节；UniVLA 把过去的动作写进 prompt，更像思维链，没有真正用上历史信息。

解读这篇的“记忆”是什么层次的东西

它存的是 VLM 产出的特征，不是图像、不是文字，也不是显式的任务状态。记忆只在一个 episode 内累积（时间步编码用的是 episode 内的 timestep），不跨任务、不检索外部数据库。所以它解决的是“这个 episode 里我刚才做过什么”，不是“以前在类似场景里怎么做”。

方法 · 全局 · §3.1–3.2

VLM 产出工作记忆，记忆库在中间，动作头在最后

问题形式化：给定当前 RGB 图像 I ∈ ℝH×W×3 和语言指令 L，策略输出未来 T 步动作 (a1, …, aT) = π(I, L)。每个动作是 7 维：相对平移 Δx, Δy, Δz，相对旋转（欧拉角）Δθx, Δθy, Δθz，以及二值夹爪 g ∈ {0, 1}。注意策略的输入里没有历史帧，历史只通过记忆库进来。

解读256 个感知 token 是怎么来的

224×224 的输入在 patch 14 的 DINOv2 和 SigLIP 上各得到 16×16 = 256 个 patch，所以 Np = 256 正好等于 patch 数。论文说 SE 瓶颈把视觉 token “压缩成紧凑的感知 token”，附录又说感知 token 通道数是 256，推算下来压缩的是通道（两路特征拼接后的宽度），token 数没变。这是按维度推的，论文没有写出 SE 模块的输入输出宽度。

未披露是不是从 CogACT 权重初始化

论文写“基于在 OXE 上预训练过的 7B Prismatic VLM”，视觉主干、DiT 动作头、推理时的自适应动作集成都和 CogACT 一致，效率表里的 “Baseline” 也没写名字。是否直接加载 CogACT 的 checkpoint 再加记忆模块微调，正文和附录都没说。

方法 · 记忆模块 · §3.3

检索、门控融合、合并：每一步在两条流里各做一遍

认知模块给出的工作记忆只反映当前时刻：

Mwk = { p ∈ ℝNp×dp, c ∈ ℝ1×dc }(2)

记忆库 PCMB 由两条流组成，每条最多 L 条：

Mpcmb = { mx | x ∈ {per, cog} },   mx = { mxi ∈ ℝNx×dx }i=1L(3)(4)

1. 检索：当前 token 作 query，key 上加时间步编码

每个记忆条目带着它的 episode 时间步 ti，用正弦编码 TE(·) 加到 key 上，value 不加。感知流把 L 条记忆堆成 LNp×dp 的张量，认知流堆成 L×dc：

Kx = [ mx1 + TE(t1); … ; mxL + TE(tL) ],   Vx = [ mx1; … ; mxL ](5)
Ĥx = softmax( qx (Kx)⊤ / √dx ) Vx,   qx ∈ { p, c }(6)

注意力之后接 FFN 构成一个 Transformer 层，叠两层得到最终的检索结果 Hp、Hc。感知流里 256 个 query token 各自看全部 L×256 个记忆 token；认知流里 1 个 query 看 L 个记忆。

2. 门控融合：逐元素决定信记忆还是信当前

gx = σ( MLP( concat[ x, Hx ] ) ),   x̃ = gx ⊙ Hx + (1 − gx) ⊙ x(7)(8)

g 是和 x 同形状的向量，每一维单独决定这一维取多少记忆、多少当前。融合结果 p̃、c̃ 被送往动作专家，同时写进记忆库。

3. 整理（consolidation）：库满时合并相邻最相似的一对

i*x = argmaxi=1..L−1 cos( x̃i, x̃i+1 ),   mxi* ← ½ ( x̃i* + x̃i*+1 )(9)

当条目数超过 L，在每条流内部计算相邻条目的余弦相似度，选最高的一对取平均。两条流各选各的，所以感知流合并的可能是 t2、t3，认知流合并的可能是 t5、t6。论文的理由是去掉冗余、保留最显著的细节和语义，让记忆保持紧凑。

解读写进库里的是融合后的 x̃，不是原始的 x

这让每条记忆都是“递归”的：t 时刻写入的条目已经混入了 t 之前检索到的历史。所以即便两帧画面一模一样（按按钮前后），它们写进库里的条目也会不同。下面的演示里可以直接看到这一点。代价是记忆内容依赖模型参数，训练时不能离线预计算。

未披露公式里没交代的几处

① 合并后的条目在 TE 里用哪个时间步（前一个、后一个，还是平均）。② 第一步记忆库为空时检索怎么处理。③ 检索层里有没有 Q/K/V 投影：公式 (6) 直接写 q K⊤，但“一个 Transformer 层”通常带投影。④ 感知条目是 256×dp 的矩阵，算余弦相似度时是展平还是先池化。⑤ 新一个 episode 开始时是否清空记忆库（从时间步编码按 episode 计来看应当清空，但没有明说）。

    解读拨一拨开关能看到什么

    FIFO 会先丢掉最早的条目，L = 4 时到 t=5 “起始画面”就没了；相邻合并不按先后丢，而是把“按下—抬起”这类连续相似的帧压成一条，最早的信息即使被合并，也以 t1–4 这样的条目留在库里。论文的检索可视化（图 10b）显示，Mikasa 的 ShellGameTouch 任务里模型的注意力几乎全压在最初几帧（球被盖住之前），这正是 FIFO 最先删掉的部分。关掉时间步编码后，画面相同的两条记忆在检索里无法区分先后。

    方法 · 动作专家与训练 · §3.4 · 附录 C

    动作专家与训练配方

    记忆条件动作专家。一个约 300M 参数的 DiT，用 DDIM 采样 10 步，预测 T = 16 步的动作块。每个去噪步里，带噪动作 token 先加上去噪步的正弦编码，再和认知表示 c̃ 拼接；cognition-attention 层提供高层语义引导，perception-attention 层从 p̃ 补充细粒度视觉细节，最后过 FFN。训练目标是预测动作与目标动作之间的 MSE，最终向量过 MLP 得到 7 维连续动作。推理时 CFG 系数 1.5。

    超参（附录表 8）。全局 batch 256（每卡 32 × 8 卡 A100，PyTorch FSDP），学习率 2×10−5，梯度裁剪 1.0，“repeated diffusion steps” 为 4（训练时每个样本重复采样 4 次扩散步，CogACT 的做法），动作块 16，感知 token 通道 256。数据增强按固定顺序做随机裁剪（90% 面积）、亮度 0.2、对比度和饱和度 [0.8, 1.2]、色相 0.05，评测时关闭。

    记忆要训练，数据就得按时间顺序喂

    流式加载：SimplerEnv-Bridge / Fractal

    每个 episode 拆成连续帧并标上 episode ID。一个 batch 尽量用同一个 episode 的连续帧填满；episode 结束了就接着填下一个 episode 的帧；下一个 batch 从上一个停下的位置继续，保证 episode 内的时间顺序。记忆长度 16。

    分组采样：LIBERO / Mikasa-Robo

    每个 batch 分成若干组，每组是同一个 episode 里的若干帧，组内保持时间顺序。附录另一句写“每次迭代从单个 episode 里随机采 16 帧，与记忆长度 16 对应”。记忆长度 16。

    疑点训练时记忆库怎么构造，论文没讲清

    附录只描述了数据加载器，没说一个 batch 里的帧是不是逐帧串行前向、把前面帧的 x̃ 写进记忆供后面帧检索，梯度是否沿时间回传，batch 跨 episode 时记忆是否清空。LIBERO 的“随机采 16 帧、组内保持顺序”意味着训练时相邻记忆条目之间隔着不定数量的帧，而推理时每次调用都写入一条，两者的时间间隔分布不同。真机数据在训练前按末端位移（>0.01 m 或转角 >0.4 rad，最多隔 120 帧）抽帧，推理时是否按同样规则决定何时写记忆也没交代。

    解读没有专门的记忆损失

    记忆模块（检索两层、门控 MLP）只靠动作的去噪 MSE 端到端学习，没有对齐、对比或重建类的辅助目标。合并操作（余弦 argmax + 平均）本身无参数。

    读懂它

    这篇真正说明了什么

    关键 insight

    1. 记忆放在特征空间，不进 VLM 的输入

    VLM 每步仍只看单帧，保持和单帧预训练一致；历史以压缩特征的形式在 VLM 之后、动作头之前注入。代价很小：单次推理 0.187 → 0.194 s，显存多 0.8 GB（L = 16 时）。

    2. 两条流互补，单独都不够

    只留认知流 63.5，只留感知流 64.6，两个都留 71.9。感知流每步存 256 个 token，承担了大部分存储；认知流每步只存 1 个 token，却和感知流贡献相当。

    3. 相邻合并 = 自适应的时间分辨率

    重复、静止的片段被压成一条，变化剧烈的片段保留更多条目，最早的关键帧不会被挤掉。FIFO 换成相邻合并，Bridge +5.2、真机 Clean Table & Count +8、LIBERO-90 +0.7。（解读：这个“分辨率”的说法是我们的概括。）

    4. 涨得最多的是真正需要记忆的任务

    真机时序任务比 CogACT 高 26，通用任务高 9；Seq. Push Buttons 从 15 到 58，Change Food 47 到 85。Mikasa 的 ShellGameTouch 88，次高 47。Fractal VM 平均只比 CogACT 高 2.9。

    容易误解的地方

    • 真机的“成功率”是按步骤计分的平均分。时序任务按细则给部分分（例如 Guess Where 抓起盖子就有 30 分），83 分不等于 83% 的试验完整完成。
    • “比 SOTA 高 X 点”比的对象每个平台不一样。Bridge 的 +14.6 和 Fractal 的 +4.6 对 CogACT，Mikasa 的 +11.8 对 PI-0，LIBERO 的 +3.3 对复现的 CogACT。对最强基线的差距分别是 +3.5（π0-Beta*）、+4.6、+11.8、+2.5（π0*，按前四套）。
    • “记忆”不跨 episode。它不是经验库，也不做相似任务检索；论文在结论里把“终身记忆”列为未来方向。
    • 认知 token 不是语言输出。它是 LLaMA 在 EOS 位置的隐状态，模型不生成任何文字。

    FAQ

    为什么 Bridge 这种短任务也涨了 14.6 分？

    Bridge 的四个任务（放勺子、放胡萝卜、叠方块、放茄子）不像按按钮那样明显依赖历史。论文把增益归于时序记忆，但没有“同一套训练流程、只去掉记忆”的对照：基线 CogACT-Large 是官方权重复测的，而 MemoryVLA 是在 20 个验证点里挑测试成功率最高的那个。两者之间除了记忆还有训练步数、数据加载方式（流式按时间顺序）和选点方式的差别。消融表里最接近“无记忆”的是只留一种记忆（63.5 / 64.6），也都高于 CogACT-Large 的 57.3。

    为什么不直接把多帧喂给 VLM？

    论文的两条理由：自注意力随长度平方增长，以及多帧输入偏离单帧的机器人预训练分布。MemoryVLA 每步只往库里加 256 + 1 个 token，并且 VLM 本身不看这些历史。附录表 17 里用多帧特征滑窗的 CronusVLA 在 Bridge 上 60.4、Mikasa 上 18.0，都低于 MemoryVLA，但这不是同一骨架下的受控对比。

    认知 token 只有 1 个，够吗？

    表 11：1 个 71.9，4 个 69.8。逐任务看 4 个 token 在 Spoon on Towel 更高（79.2 vs 75.0），Carrot 和 Eggplant 更低。作者推测单个 4096 维 EOS token 的语义容量已经足够。差距是 2 次成功 / 96 次，只能说“加到 4 个没看到收益”。

    记忆长度为什么不是越长越好？

    Bridge 上 16 最好，64 掉到 67.7；真机 Clean Table & Count 上 256 最好（84），512 是 81；LIBERO-90 上 16 和 32 都是 95.6。作者把最优长度和 episode 长度挂钩。论文没有解释长度变长为什么会变差；结合上面的长度统计，L = 64 时 Bridge 的大部分 episode 只合并很少几次，L = 512 时真机多数 episode 不触发合并，较长的 L 等于部分关掉了整理机制（解读）。

    这个记忆模块能直接装到别的 VLA 上吗？

    论文只在一种骨架（Prismatic-7B + DiT）上做了实验。机制本身只需要一组“每帧一个或几个语义 token + 一组视觉 token”和一个能做 cross-attention 条件的动作头，π0 这类把 VLM 和动作专家放在同一注意力里的结构需要另找插入点。这一点论文没讨论（解读）。

    局限与疑点

    作者承认的，和我们读出来的

    论文自己提到的

    • 对未见相机视角明显不鲁棒：Pick Coke Can 从 92.0 掉到 42.0，Move Near 从 76.0 掉到 58.0（附录 B.2）。
    • 记忆长度需要按 episode 长度调：仿真 16，真机时序任务 256（附录 G）。
    • 未来方向：memory reflection，把长期记忆对齐到 LLM 输入空间，在嵌入空间里做思维链；lifelong memory，把常用经验蒸馏成永久表示，跨场景、任务和本体泛化。反过来说明现在的记忆既不回到 LLM，也不跨 episode。

    我们读出来的

    • 疑点缺“同训练、无记忆”的对照，记忆的净贡献和训练流程、选点方式的差别混在一起（见 FAQ 第一条）。
    • 疑点仿真结果取测试基准上最好的验证步（Bridge 20 个、Fractal 16 个、LIBERO 每 1k 步一个），基线是单个发布权重或原文数字。在 24 次试验的粒度上挑最大值，会系统性偏高。
    • 疑点Mikasa 正文“每个任务都最好”与表 4 不符（InterceptMedium 24 vs 42，RememberColor3 44 vs 59）。
    • 疑点表 3 与表 17 的 CronusVLA / 4D-VLA 数字互相错位。
    • 疑点Fractal 的总试验数：正文写 336 个变体 “yielding 2,856 trials”，附录写 “producing 2,352 evaluation trials”。
    • 疑点训练时记忆如何构造、梯度是否跨时间回传、推理时何时写入、episode 之间是否清空，都没写；训练与推理的帧间隔可能不一致。
    • 疑点效率表没写记忆长度；L = 256 时 65,536 个感知记忆 token 的开销未测。“82.5 Hz”是 16 / 延迟。
    • 疑点消融只在 Bridge 上做、每项 96 次试验，没有报告多种子或置信区间，差距 2–8 次；仿真鲁棒性的 Base 与主表对不上，部分分布外变体高于 Base。
    • 真机通用任务正文说“每个任务都超过最强基线”，Stack Cups 是 93 平 CogACT 的 93。
    • 合并后条目的时间步编码、空库时的检索、检索层是否带投影，均未披露。

    本文的主要基线和骨架来源：Prismatic VLM 输出认知特征，DiT 动作头据此去噪动作块，推理时用自适应动作集成。
    Prismatic VLM
    DINOv2 + SigLIP 双视觉编码器接 LLaMA 的 VLM 家族；OpenVLA 和 CogACT 用的就是它在 OXE 上预训练后的版本。
    工作记忆 Mwk
    当前时刻的感知 token p 和认知 token c，类比大脑里短时保持信息的神经活动。
    感知 token p
    视觉特征经 SE 瓶颈压缩后的 256 个 token，保留低层视觉细节（类比 verbatim 记忆）。
    认知 token c
    LLaMA-7B 在 EOS 位置的 4096 维输出，代表高层语义（类比 gist 记忆）。
    PCMB
    Perceptual-Cognitive Memory Bank，感知-认知记忆库：两条流，每条最多 L 个条目，存融合后的 p̃、c̃。
    TE / Timestep PE
    按 episode 内时间步计算的正弦位置编码，检索时加在 key 上。
    门控融合
    g = σ(MLP([x, H]))，x̃ = g⊙H + (1−g)⊙x，逐元素决定用多少记忆。消融里的对照是直接相加（Add）。
    Consolidation / Token Merge
    记忆整理：条目数超过 L 时，在每条流内合并余弦相似度最高的一对相邻条目（取平均）。对照是 FIFO（丢最早的）。
    SE 瓶颈
    Squeeze-and-Excitation 结构的压缩模块，这里用来压缩视觉 token 的通道。
    DiT / DDIM / CFG
    扩散 Transformer 动作头；10 步的确定性采样器；分类器无关引导，系数 1.5。
    自适应动作集成
    CogACT 的推理策略：每步都调用模型，把重叠的历史动作块按相似度加权平均。本文 α = 0.1，Bridge 窗口 7，Fractal 窗口 2。
    VM / VA
    SimplerEnv-Fractal 的两种评测：Visual Matching 尽量还原真实场景外观；Visual Aggregation 改背景、光照、干扰物、纹理等做压力测试。
    Mikasa-Robo
    专门考察记忆的操作基准，本文用其中 5 个任务：ShellGameTouch、InterceptMedium、RememberColor3 / 5 / 9。
    步骤计分
    真机时序任务的评分方式：按子目标给部分分，满分 100。
    OXE / RLDS
    Open X-Embodiment 跨本体机器人数据集；RLDS 是它使用的 episode 数据格式。
