Motus2

A Self-Evolving General World Model for Dexterous Manipulation

一套共享权重的视频-动作模型，只靠切换哪些 token 加噪、哪些 loss 打开，就能分别当 策略（出动作块）、模拟器（预测这个动作的视觉后果）和 评估器（给后果打进度分）。三者串起来，推理时用来挑动作，训练时用来改策略。

数据侧，主干先在约 13 万小时的人类第一视角视频上预训练（先单目，再双目加手部动作），再用 100 多小时机器人与人机对齐数据做域适配。另有一个轻量触觉专家，在灵巧手上用最新的力信号修正即将执行的动作。

§1 引言 · §2 相关工作

它要解决什么问题

论文的出发点是：通用具身智能体应当在一个统一系统里完成感知、预测、行动、评估和改进，而现有的机器人基础模型大多只做了“行动”这一步。

作者指出了三处不足。

  1. 只靠模仿。今天的机器人基础模型主要在精选的动作示范上训练。对齐本体的示范很贵；模仿本身也不知道一个动作好不好，模型没法从自己的执行结果里继续改进。
  2. 人类数据难以直接迁移。第一视角的人类视频能提供大规模的手-物交互先验（双目还能提供深度线索和更准的 3D 手部姿态），但指尖打滑、抓握成形、松手这类接触事件单看画面很模糊；第一视角下手会挡住物体，有些后果要过一会儿才显现。这是论文后面做机器人域适配、长时程上下文和触觉反馈的动机。
  3. “世界模拟器 + 动作头”缺了评估。world–action model（WAM）能当策略，action-conditioned world model（AC-WM）能当模拟器，前作 Motus 已经用 UniDiffuser 式的联合建模把二者放进同一个模型。但预测出的未来本身不说明它是否推进了任务，所以还需要第三个接口：评估器，也就是价值模型。

作者把核心问题写成一句话：如何在一个共享模型里实现这些因果接口，同时不把未来观测暴露给动作预测；又如何把结果价值转换成策略更新？

解读“在世界模拟器上接一个动作头”不够，原因有两层。其一，没有评估器，模拟器想象出来的后果无法用来挑选或改进动作，失败数据也只能丢掉或被错误地模仿。其二，如果动作 token 能看到同一块的未来视频，部署时每一步都得先把视频生成出来，控制就被视频生成的开销拖住。Motus2 的做法是用“动作优先”的掩码切断这条依赖，让三个接口共享权重但各司其职。

§3.1 Overview · §3.2 General World Modeling

一套权重，三个接口

作者把任务写成部分可观测马尔可夫决策过程：观测 ot = (图像, 本体感受, 可选触觉)，因为手经常挡住物体和接触点，当前观测不够当马尔可夫状态，所以策略条件在历史上。实际中，核心模型用上下文 ct 表示历史：语言、当前本体感受，以及由工作记忆机制（见记忆一节）提供的编码后视觉历史。

给定上下文，设 At 为可执行的动作块，Zt 为它对应的未来观测 latent，Yt 为离散化的任务进度值。从机器人域中训练开始，三者的联合密度按“动作优先”的顺序分解：

Eq. 2pθ(At, Zt, Yt | ct) = πθ(At | ct)policy (WAM) · pwmθ(Zt | ct, At)simulator (AC-WM) · pvmθ(Yt | ct, At, Zt)evaluator (VM)

这三个因子是同一个共享参数模型的三种调用方式，并不是三个分别训练的网络。给分支排序用的分数是评估器的条件期望 Vθ(ct, At, Zt) = 𝔼[Yt]（Eq. 3）。

token 怎么排：chunk 自回归

从中训练开始，每个训练窗口排成“干净的历史观测 + 若干个动作优先的块”：x = (Zctx; B1; …; BM)，每块 Bj = (qj; Aj; Zj; Uj)，其中 qj 是可选的本体感受，Uj 是只读的价值查询 token。

  • 块内：动作 token 读不到本块的未来视频和价值；未来视频 token 可以读当前动作；价值查询可以读两者，但对其他所有 token 隐藏。于是块内依赖是 Aj → Zj → Uj。
  • 块间：因果且有窗口，块 j 可以用之前的干净观测，永远看不到后面的块。自回归发生在块与块之间，块内的一串低层动作由 flow matching 一起生成。作者称之为 chunk-autoregressive。
  • 其余：主干从基础视频扩散模型初始化（附录 E：Wan 2.2-TI2V-5B）。双目的左右视图 latent 共享时间和竖直方向的 RoPE 坐标，水平方向用错开的区间；本体感受、动作和价值查询进入同一个 Transformer 计算，语言走交叉注意力。

按轨迹类型分配监督

掩码保证了依赖方向正确，但它不能判断一条录下来的动作值不值得模仿。所以每条轨迹只路由到它能正确监督的因子：

  • policy 从中训练开始，只有精选的成功轨迹会打开动作监督。
  • simulation evaluation 失败轨迹、次优轨迹，以及与任务无关的交互，只进入模拟或评估模式。这时录下的动作只是干净的条件变量，不是模仿目标。模型从这些数据里学转移和结果，但不会学着复现坏动作。

部署时只查询动作

训练好以后，普通控制只查询动作因子 πθ(At | ct)，未来视频和价值只在规划或策略优化时才生成。因为动作 token 看不到本块的未来视频，这样做不会改变动作的分布。论文强调这保留了视频-动作联合训练的好处，又不必在每个控制步都做一次未来预测（引用 Fast-WAM、GigaWorld-Policy）。默认部署时，动作块用 5 步 flow-matching 去噪采样（附录 E.3）。

§3.2 Data-scaling curriculum · §4 · 附录 B–E

数据课程：从人类视频到目标机器人

训练分四段。前两段只用人类第一视角数据，后两段才进入机器人域。动作优先掩码和监督路由也是从机器人域适配开始才启用的。

  1. 预训练 · Stage 1
    只训视频通路
    • 单目第一视角：先低分辨率 500K 步，再高分辨率 340K 步

    • 没有动作和价值 token
  2. 预训练 · Stage 2
    视频-动作联合
    • 多分辨率双目第一视角视频 + 人手动作，450K 步
    • 块内视频与动作双向可见（联合掩码），价值 loss 关闭

  3. 中训练 Mid-training
    机器人域适配
    • 100 多小时：机器人轨迹 + 几十小时人机对齐数据
    • 换成动作优先掩码，三种模式混合训练
    • 640×384 双目，W = 8，κ = 2，历史 1–3 块
  4. 后训练 Post-training
    目标机器人 SFT 与三个扩展

§3.3 Value-Guided Closed-Loop Self-Evolution · 附录 E.3

闭环：规划与 MBRL

动作优先的分解让“提候选 → 想后果 → 打分”可以按顺序执行。要让模型自我改进，还需要把评估器的反馈送回策略。

评估器学的是“相对进度”

沿用 VLAC 的相对进度定义。对成功轨迹中从时刻 t 开始、长度为 Δt 的片段，目标是

Eq. 8 / 9rt = + Δt / (T − t)　（成功轨迹的片段）　　rt = − Δt / (T − t)　（失败遥操作、任务无关交互的片段）

其中 T 是轨迹总长。正目标落在 [0, 1]，衡量这一段相对“剩余任务长度”推进了多少。只有正样本，评估器学不会怎样给偏离任务的行为打分，所以用两类负样本补上：失败的遥操作轨迹（抓不准、意外接触、偏离指令流程）和与任务无关的交互。正负值再离散成 Eq. 6 里的类别目标 Yt。

两种用法

  • 推理时规划（Best-of-N，滚动时域）：提 N 个动作块，逐个模拟并打分，执行分最高的那块 Ai*，i* = argmax Vi，拿到真实观测后重复。每执行一块就重新规划，减少对长想象链的依赖。论文没有给出规划时的 N。
  • 训练时 MBRL（DiffusionNFT）：规划只能在现有策略的分布里挑，改变不了“提议分布”本身。MBRL 把评估器的分数喂回动作通路，用 DiffusionNFT 把标量分数变成 flow-matching 策略更新，模拟器和评估器保持不动。

MBRL 的核心是把分数变成 [0, 1] 的“最优性权重”，再用它在两个隐式速度场之间插值：

Eq. 11r̂i = 0.5 + 0.5 · clip( (Vi − mean(V)) / max(std(V), ε), −1, 1 )
Eq. 12 / 13v+i = (1 − β)vref,i + βvθ,i，　v−i = (1 + β)vref,i − βvθ,i，　ℒNFT = 𝔼i[ r̂i‖v+i − vtari‖² + (1 − r̂i)‖v−i − vtari‖² ]

mean 和 std 只在策略生成的候选上算（总体标准差），ε 防止方差接近零时数值不稳。每组候选另外放入一条真值“动作-未来”对，固定 r̂ = 1 作为正锚点，不参与均值方差计算。vref 来自 EMA 参考策略，更新时固定。直观地说：高分候选让在线策略的速度场朝它靠拢，低分候选让策略朝反方向走，r̂ ≈ 0.5 的候选两边抵消，策略留在参考附近。1/β 相当于强化引导的强度。预测出的未来 Zi 只通过分数 Vi 影响更新，不会作为输入暴露给动作速度预测器。

MBRL 的工程实现

候选生成、价值打分、参考目标构造和策略优化四个阶段吞吐不匹配，串行执行会让昂贵组件空转。作者参考 AcceRL 做了基于 Ray 的宏观异步流水线，各阶段用有界 FIFO 缓冲解耦。附录 E.3 给出的设置：

  • 每个前缀从离线数据采样，含 1–4 个块；每个前缀生成 8 个策略候选 + 1 条真值候选；想象时域只有 1 个块。
  • 动作采样 4 步去噪，未来视频采样 8 步去噪。DiffusionNFT 取 β = 0.1，每个候选采一个噪声水平。
  • EMA 参考策略衰减 0.99，每 10 次训练更新发布一次；参考版本过旧或超过 600 秒的样本丢弃。
  • 只优化动作相关参数，共享的视频主干和价值组件都冻结。
§3.4 Working Memory · 附录 E.3

工作记忆：能看到多久以前

闭环只能用 ct 里保留下来的证据。有界上下文会丢掉任务早期看到、后面又需要的信息，手也可能在后面的画面里挡住物体。作者把“可访问的历史”当成一个显式的设计维度，做了三种方案：

  • 滑动窗口（默认）：固定成本的流式方案。部署时只保留真实观测到的视觉 latent（不用想象出的），KV cache 只存最近的干净观测，执行完一块就追加新观测、挤掉最旧的。时间 RoPE 是窗口相对的，挤掉之后剩下的视频 key 会重新定位，保证位置落在训练见过的范围内。附录 E.3：W = 8，κ = 2，两块的流式缓存。
  • 全局自回归：保留全部历史干净 latent，用整条 episode 的时间坐标，每个预测块都能看到完整历史。代价是 KV cache 和注意力开销随 episode 长度增长（N 个 latent 帧后保留 NL 个视觉 KV token）。
  • 混合工作记忆：MemoryWAM 式。保留开头的 2 个全分辨率锚点帧和最近 4 个全分辨率帧，更早的中间观测压成持久的记忆 token（每个 latent 帧 8 个）。

两种长历史变体都在完整 episode 上训练，长度差异大，所以作者把多条 episode 打包进一次注意力调用，用块对角因果掩码隔开，各自生成 RoPE，padding 不计 loss。这只改变计算布局，与分开处理等价。拖动下面的滑块，看随着任务推进，三种方案各自还能“看见”哪些帧。

§3.5 Tactile Expert · 附录 E.3 · §5.6

触觉专家：在去噪的最后一段接入力信号

工作记忆扩展了视觉历史，但接触状态单靠视觉仍然可能模糊。作者想把高频的触觉证据接进来，又不想每来一段触觉就把整个主干重跑一遍。办法是挂一个轻量专家，复用主干算好的中间结果。

结构：一条窄而深的旁路

  • 规模：30 层 Transformer，隐藏宽度 128，4 个注意力头，FFN 宽度 512。每层与共享主干的对应层一一配对。
  • 读什么：每层对“触觉 token + 中间动作 token”做自注意力，同时读主干对应层缓存好的 K/V。
  • 主干只跑一次：参照 T-Rex，主干把整个 48 个动作的块从 σ = 1 去噪到固定的 σc = 0.2，在这个中间状态刷新动作的 K/V，与可见的视频上下文 K/V 拼起来。这份逐层缓存被 detach，供专家反复使用。
  • 专家分段收尾：动作频率 30 Hz，一块切成 8 个子块，每个 6 个动作、0.2 秒。每执行一个子块之前，专家拿紧挨着它之前的触觉窗口，完成这个子块从 σc 到 0 的最后一步更新。同一份中间动作块和 KV cache 在 8 次调用里复用。

关键 insight · 常见误解 · FAQ

读懂它

值得带走的几个设计

  1. 三个接口的区别只在“哪些 token 加噪、哪些 loss 打开”。没有三个网络，也没有三个独立的头：同一个 DiT，同一张动作优先掩码，靠 (σz, σa) 和 (wz, wa, wv) 切换。评估器唯一多出来的是价值查询 token 和 201 bin 的类别读出。
  2. 动作优先的掩码同时解决了两件事。动作不看本块未来视频，所以部署时可以只去噪动作；视频 token 能看动作，所以同一个模型天然是动作条件的模拟器。预训练阶段则保持块内双向，先把视频-动作的联合先验学好，到机器人域才切换。
  3. 失败数据有用，但不能拿来模仿。成功轨迹训策略，失败、次优和无关交互只训模拟器和评估器。这让同一批数据按“能正确监督什么”被分别利用。
  4. 规划改“选哪个”，MBRL 改“提什么”。两者用同样的三接口，一个在推理时从当前分布里挑，一个在训练时移动分布，实验里二者可以叠加。
  5. 触觉走旁路、按双速率运行。主干每块跑一次，专家每 0.2 秒用新触觉修正一次，不必重跑主干。

容易误解的地方

  • “自进化”不等于在线真机强化学习。论文实际做的 MBRL 是：从离线数据采前缀，想象 1 个块的后果，用冻结的评估器打分，只更新动作相关参数。论文没有报告“更新策略 → 采新真机数据 → 再训模拟器和评估器”的多轮迭代。
  • policy 模式也在训视频。policy 模式的 loss 开关是 (1, 1, 0)，未来视频也被加噪和监督；只是部署时只读动作因子。
  • 价值不是成功概率。论文明确说价值用于排序，没有校准。
  • 触觉预测不在部署链路里。未来力的预测只是训练时的辅助目标；Sharpa Wave 的形变图也只作条件。
  • 缩放规律测的是人手动作误差。Figure 5 说明双目人类数据越多、人手动作预测越准，并没有直接给出机器人成功率随数据量的曲线。

FAQ

评估器的分数靠得住吗？

论文给的证据有三类。定性上，附录 F 的八条轨迹里，成功轨迹都升到 0.63–0.65，失败轨迹在进度丢失后下降。定量上是间接的：用这个分数做 Best-of-N 规划带来 +2.5，做 MBRL 带来 +7.5（表 3）。论文没有报告价值模型本身的排序准确率或与真实结果的相关性。

解读还有一个值得注意的细节：Put Phone 的失败轨迹 (h) 中途峰值 0.60，与成功轨迹的终点 0.65 很接近，它是在后面反复盖不上盖子时才掉下去的。而 MBRL 的想象时域只有 1 个块，打分看的是一小段后果，这种“看上去快成功了”的状态能否与真正会成功的状态区分开，论文没有直接回答。

自进化到底进化了什么？

按 §3.3 和附录 E.3，被更新的只有策略的动作相关参数；共享的视频主干（也就是模拟器的大部分能力）和评估器都冻结。所以进化的是“提议分布”：高分候选的方向被加强，低分候选的方向被削弱。模拟器和评估器本身在这个循环里不变。

为什么动作 token 不能看本块的未来视频？

论文的核心问题里就写了“不把未来观测暴露给动作预测”。如果动作依赖本块未来视频，部署时就必须先把视频生成出来才能出动作；而且作为 π(A|c) 这一因子的策略，本来就不应条件在尚未发生的观测上。作者的做法是预训练保留块内双向（学联合先验），到机器人域中训练时切成动作优先。

为什么触觉不直接放进主干？

论文给的理由是：要接入高频触觉证据，又不想为每段触觉重跑整个主干。于是主干每块只到 σc = 0.2，剩下的一步交给读缓存的专家。

解读另一个现实原因写在局限里：可穿戴触觉数据很难跨本体扩展，人类第一视角数据基本不带触觉。把触觉限制在后训练的旁路里，主干就能继续吃 13 万小时的无触觉数据。

人类数据和机器人动作空间怎么对上？

预训练阶段，人手 21 个 MediaPipe 关键点通过 IK 重定向到第一代 Wuji 手的 20 维关节空间；统一的 134 维表示记录双手腕部位姿和指关键点。中训练加入用 Wuji Human Gloves 采集的人机对齐数据，并用机器人轨迹做适配；后训练时 Wuji Hand 2 和 Sharpa Wave 用各自的原生关节角。表 2 中 Pretrain-SFT 与 Midtrain-SFT 相差 33 个百分点，说明这一步域适配很关键。

§7 Limitations · 我们的阅读

局限与疑点

论文自述局限与未来工作

  • 可穿戴触觉监督难以跨本体扩展，这是作者认为的首要局限。触觉手套无论戴在人手还是机器手上，都会随手的构型变形；即使没有外部接触，材料拉伸和内部织物接触也会产生噪声，难以与有意义的物理接触区分。
  • 灵巧手与人手在几何上不同构：小指常被拉长，有些手明显更粗更大，一种手套版型没法同时适配人手和机器手。用人类手套采的触觉数据不能直接迁移到戴专用手套的灵巧手上，这限制了跨本体触觉学习的规模和可靠性。
  • 未来工作：数据侧，期待可穿戴触觉材料让全手触觉的多模态第一视角采集可扩展，更拟人的灵巧手缩小形态差距；模型侧，期待更强的视频基础模型和统一多模态模型带来更长时程、更可信的多模态模拟，把视觉、语言、动作、触觉和价值统一进同一个生成与决策过程。

解读我们读出来的疑点

  1. π0.5 全 0% 的基线强度存疑。五个任务全部 0%，WAN-SFT 也全部 0%。论文说 SFT 数据与接口一致，但没有给出每个任务的 SFT 数据量、π0.5 如何适配 20/22 自由度灵巧手的动作空间、训练了多少步。全零更像是适配或数据量问题，而不是能力差距的刻画。
  2. 评测规模小。每格 20 次，1 次 = 5 个百分点。MBRL/规划的增益合计只涉及几次成功，没有置信区间或多种子。
  3. “自进化”在实验里只做了一轮。MBRL 的前缀来自离线数据，想象时域 1 块，模拟器和评估器冻结。标题里的闭环自进化，实验上验证的是“单轮、离线前缀、想象打分”的策略改进。
  4. 正文与附录不一致。§5.4 描述的 Screw Bulb（0.34 → 0.81）与附录 F 实际展示的四任务图对不上，且 Cut Reeds、Make Tea 不在评测任务列表中。
  5. 数据量对不上。表 1 双目数据合计 17,400 小时（7,000 + 6,000 + 1,200 + 2,000 + 1,200），而缩放实验的最大嵌套子集标为 20k 小时原始双目数据，论文没有解释差额。
  6. 记忆实验缺少滑动窗口基线，也没有延迟数据。两种长历史变体都只训练 10K 步，混合记忆可能欠训练；仿真平台也没有写明。
  7. 触觉实验偏薄。两个任务、每个只在一种手上测、各 20 次；没有拆开“修正”与“预测辅助损失”各自的贡献，也没有和“把触觉直接拼进主干”之类的方案比较。
  8. 算力与延迟没有报告。预训练共 129 万步（500K + 340K + 450K），5B 级主干；规划需要对 N 个候选各生成一次未来视频，论文没有给出规划模式下的控制频率，也没有给出 MBRL 的 GPU 规模和时长。

和 ME-Dex 1.0 的关键区别

解读两篇都是世界模型路线，但对触觉的定位几乎相反。

  • ME-Dex 1.0 的主张是触觉和视频一样是世界状态的观测，应该和视频一起作为未来观测来预测。触觉动态由此进入共享表示，动作生成在联合去噪时能直接用到它。代价是需要大量视觉-触觉-动作配对数据，所以它要专门做一个数据引擎，在仿真回放中补录力信号，还要用统一的手模型和自编码器处理异构传感器。
  • Motus2 让主干保持纯视觉-动作，触觉通过旁路专家在最后一步修正动作。好处是主干可以用 13 万小时不带触觉的人类数据预训练，触觉只在后训练用少量真机数据；专家每 0.2 秒修正一次，不必重跑主干。代价是模拟器和评估器看不到触觉，规划和 MBRL 无法推理接触后果；力预测只影响旁路专家，不塑造主干的世界表示。

换句话说，如果问“触觉是条件还是被预测的观测”：ME-Dex 1.0 明确选了后者；Motus2 两者都做了一点，但真正进入部署链路的只有条件这一面，它的“世界模型”部分仍然是视觉的。两篇放在一起读，正好对应了触觉进入世界模型的两种代价取舍：要表示层面的统一，就得解决数据；要数据可扩展，触觉就只能晚一点、浅一点地接入。

给定候选动作预测未来观测，充当 simulator 接口。
价值模型VM
评估预测结果、给出任务进度分，充当 evaluator 接口。
动作优先掩码action-first mask
块内 A 看不到 Z 和 U，Z 能看 A，U 能看 A 和 Z，其他 token 看不到 U。中训练起启用。
块自回归chunk-autoregressive
块与块之间因果自回归，块内的一串动作由 flow matching 一起生成。
价值查询 tokenvalue query U
只读的查询 token，读出 201 个 bin 的进度分布；其期望 V 用于排序。
loss 开关loss gates
(wz, wa, wv)，与两路噪声水平一起决定当前是哪种训练模式。
监督路由supervision routing
成功轨迹训策略；失败、次优与无关交互只训模拟器和评估器。
相对进度relative progress
片段目标 ±Δt/(T−t)，来自 VLAC。
κ 与 W
κ 是每块的 latent 帧数（这里为 2），W 是一个训练窗口里的 latent 帧总数（Stage 2 为 12，之后为 8）。
中训练mid-training
预训练与目标机器人后训练之间的机器人域适配阶段，100 多小时数据。
Best-of-N 规划test-time planning
提 N 个候选、模拟、打分、执行最高分，每步用真实观测重新规划（滚动时域）。
DiffusionNFT
把标量分数变成 flow-matching 策略更新的方法：用 r̂ 在正、负两个隐式速度场之间加权，参考策略为 EMA。
最优性权重r̂
候选分数在组内标准化后截断映射到 [0, 1]；真值候选固定为 1。

用 Ray 把前缀采样、想象与打分、参考目标构造、策略优化解耦，中间用有界 FIFO 缓冲。
窗口相对 RoPE
滑动窗口挤掉旧帧后，剩余视频 key 的时间坐标重新定位，保持在训练范围内。
全局自回归global AR
保留全部历史干净 latent，使用整条 episode 的时间坐标。
混合工作记忆hybrid memory
MemoryWAM 式：2 个锚点帧 + 最近 4 帧全分辨率，更早的帧压成记忆 token。
episode 打包packing
多条完整 episode 放进一次注意力调用，块对角因果掩码隔开，等价于分开处理。
σc
主干去噪停下的中间噪声水平（0.2），剩下的一步交给触觉专家。
T-Rex
触觉反应式灵巧操作的前序工作，Motus2 的触觉专家沿用了其“主干去噪到中间、专家收尾”的思路。
BoxTrim
论文的第一视角数据时间清洗流程，切掉快速转身、轨迹突变和双手失踪的区间。
