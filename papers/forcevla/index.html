01 · 问题

接触密集任务靠的是力，而现有 VLA 只看图和话

OpenVLA、π0 这类 VLA 用预训练的视觉-语言模型理解场景和指令，然后输出动作。插插头、插 U 盘、擦白板、削黄瓜这类任务，成败取决于接触：有没有对准、压得够不够、是不是已经顶住了。

作者在引言里指出两个缺口：

  • VLA 基本不接力信号。一旦视觉被遮挡或者看不清，策略就没法判断接触状态，于是动作僵硬甚至失败。
  • 不同阶段需要的力不一样。抓取时要轻，插入时要受控，贴面擦拭时要保持柔顺接触。现有方法没有机制去感知这种随阶段变化的需求。

论文的回答是：力应该作为“一等模态”进入 VLA，而且融合方式要能随上下文切换，于是有了 MoE 形式的融合模块。

§5 开头论文要回答的四个问题

  1. 和“直接把力喂进去、不做专门融合”的基线相比，ForceVLA 整体有没有更好？
  2. 换物体、换环境条件、换任务条件时，能不能泛化？
  3. FVLMoE 这种融合方式是不是最优的？（融合位置与方式的消融）
  4. MoE 能否学到有意义的路由，把不同输入分给不同专家？
02 · 方法

π0 不动，在 VLM 和动作专家之间插一层 FVLMoE

§3 Problem Formulation输入输出

每个时刻的观测是 Ot = {Vtb, Vth, st, ft}：

  • Vtb、Vth：第三人称相机和腕部相机图像。
  • st ∈ ℝ7：TCP 位置 (x, y, z)、欧拉角 (α, β, γ) 和夹爪宽度。
  • ft ∈ ℝ6 = {ftx, fty, ftz, mtx, mty, mtz}：作用在 TCP 上的估计外力和力矩（wrench），表达在世界坐标系。

给定语言指令 L，策略 π(At | Ot, L) 输出一个动作块 At = {at, …, at+H−1}。动作是目标 TCP 位姿加夹爪宽度（§4.3）。

解读公式里只有当前一帧 ft，没有力的历史窗口。论文也没有给出力的采样率、归一化方式和控制频率。

§4.2四个关键设计，以及作者给的理由

  1. 力在 VLM 之后进入。作者说这是“经过大量实验”确定的，把 FVLMoE 比作负责整合的“更高层皮层联合区”。实证依据是表 3 的消融：在 VLM 之前注入力会破坏预训练表示。
  2. 整个力信号只占 1 个 token。原始 6 维读数经线性层 φF 投到 2048 维，接在 VL 序列末尾：Ein = [EVL; EF]。
  3. 先共享一层 encoder，再做稀疏 MoE。encoder 层（自注意力 + FFN）让力 token 和所有 VL token 先互相看一遍，然后每个 token 由 router 选 1 个专家（E = 4，top-1），专家输出经残差加回。
  4. 用加法注入动作生成。FVLMoE 输出投影到动作专家宽度 1024，取序列末尾 Haction 个 token 作为 GFVLMoE，逐元素加到动作 token Ssuffix 上。没有用 cross-attention。

解读第 4 点有个细节：G 取的是融合序列“末尾”的 Haction 个 token。力 token 在最末，一定被选中；其余是序列末尾的 VL token（π0 的前缀里语言在图像之后，所以大概率是语言 token）。论文没有给 Haction 的数值，也没讨论为什么按位置截取。

解读G 只依赖 EVL 和 ft，与去噪步 τ 无关，一次推理算一遍就能在所有去噪步复用。所以力信息的更新频率等于“整块重规划”的频率。

§4.1 · 附录 B训练与推理

05 · 读懂它

这篇真正说明了什么

关键 insight

  1. 融合位置比“有没有力”影响更大。同样把力接进 π0，表 3 里结果从 0% 到 80% 不等。这是全文最硬的结论。
  2. 直接加力收益很小，甚至有害。π0-base 直接接力：主结果 +2.9 点，泛化平均 −7.0 点；π0-fast 直接接力：主结果 −16.8 点。
  3. 视觉不可靠时力最有用。遮挡设置下 90%，领先最好的基线 30 点，是所有设置里差距最大的一个。
  4. 它是纯模仿学习的策略。力只作为条件输入，模型不预测未来的力，也不输出力指令；动作仍是目标位姿加夹爪宽度。解读“柔顺”靠的是策略根据力读数改变下一段轨迹，底层控制器是什么论文没交代。

容易误解的地方

  • 澄清“MoE”不是把 π0 换成 MoE 骨干，只是 VLM 和动作专家之间新加的一小段：1 个 encoder block 加 1 个 4 专家的 MoE 层。VLM 和动作专家仍是 π0 原样。
  • 澄清专家没有被指定为“力专家”或“视觉专家”。router 对每个 token（包括全部 VL token）独立选一个专家，分工是训练出来的。
  • 澄清这里的“力”是估计的末端 wrench，只有 6 个数、一帧，不是指尖触觉阵列。
  • 澄清“提升 23.2%”是百分点，参照的是不接力的 π0-base。
  • 澄清ForceVLA 不是每个任务、每个设置都最好：Pump Bottle、Wipe Board-1、Unstable Socket 都有基线更高。

FAQ

为什么不直接把力拼成一个 token 喂给 VLM？

论文表 3 正好测了这种做法。“linear before VLM”（力线性投影后在 VLM 之前送入）是 55%，“MoE before VLM”是 0%，都不如在 VLM 之后融合（80%）。作者的解释：改变预训练 VLM 的输入表示会扰乱它已经学好的特征分布，削弱它处理视觉和语言的能力。π0-fast 直接接力后大幅下降，作者也给了类似的解释。

解读55% 仍高于不接力的 45%，所以 VLM 前注入并非完全不可行。这个消融只有一个任务、每种配置约 20 次，60% 与 80% 的 95% 区间是重叠的（见 §06）。同一时期的 Tactile-VLA 恰好把触觉放进了 VLM 前缀，目标是借用 VLM 的语义做推理（见 §07）。

把力直接拼到 state 上不行吗？

论文这就是基线 π0-base w/ F。主结果平均从 37.3 升到 40.2，涨得很少；表 3 里对应的“concate after VLM”是 60%，低于 FVLMoE 的 80%。作者的结论是：光有力数据不够，融合方式才是关键。

解读泛化实验里这种接法的平均分反而比不接力低（31.96 对 38.93）。

为什么用 MoE？换成普通 MLP 行不行？

论文动机是力的需求随任务阶段变化，MoE 可以按上下文把 token 路由到不同专家；多任务和按模态处理也是 MoE 的强项（§1、§4.1）。证据是附录 C 的路由图。

解读论文没有“保留 encoder 层、去掉 MoE（或换成单个同宽 MLP）”的消融。所以 80% 对 60% 的提升里，多少来自 MoE 路由，多少来自新加的那层 2048 维 encoder（力 token 和 VL token 通过自注意力充分交互），目前拆不开。这是方法部分最关键的缺口。

力是时间序列，为什么只用一帧？

论文公式里只有当前的 ft ∈ ℝ6，经线性层投成 1 个 token。闭环靠的是每次推理都读新的 ft+1（图 3）。

解读单帧能表达“现在有没有顶住”，但看不出“力在变大还是变小”。而且力只在每次整块推理时更新一次，块内执行是开环的。论文没给动作块长度、执行步数和推理频率，没法估算实际反应延迟。Motus2 的触觉专家正是冲着这个问题去的（见 §07）。

力是从 F/T 传感器读的吗？

论文用的是 TCP 上的估计外力（estimated external wrench），表达在世界坐标系。局限部分承认估计值可能达不到高保真直接测量的精度，对触觉极敏感的场景尤其如此。

路由图能证明专家学会了“按阶段分工”吗？

论文作者认为插插头和削黄瓜表现出明显的时间分工，擦白板则一直偏好同一个专家，并把 Expert 0 看作通用专家。

解读证据偏弱：一是统计混合了所有 token，二是开环，三是没有把路由和成败或者和力的大小关联起来。更有说服力的做法是只看力 token 的路由，并对照同一时刻的力曲线。

06 · 局限与疑点

论文承认的两条，和我们读出来的十条

论文自己承认的（§6 Limitation）

  1. 用的是估计外力，精度可能不如高保真直接测量；可以考虑更好的传感器或标定技术。
  2. 实验主要在自带（通常昂贵）力/力矩感知的平台上做，限制了普及；作者正在评估外接或后装力传感器的低成本平台。

解读我们读出来的

  1. 试验次数少，区间很宽。20 次试验下，80% 的 95% Wilson 区间约为 58–92%，60% 约为 39–78%。表 3 里 FVLMoE（80%）和“concate after VLM”（60%）的区间是重叠的。
  2. 部分百分比和正文写的试验次数对不上。Pump Bottle 写的是 20 次，20 次只能得到 5 的倍数，但图 5 里有 33、67、83，更像是 6 或 12 次。Wipe Board 写的是 10 次，但 91、64、45、27、9 都是 1/11 的倍数（11 或 22 次）。表 2 的 48、32（25 次？）和 66.67、77.78、88.89、44.44（9 次？）也说明各设置的次数不同，而论文没给。
  3. 没有能单独验证 MoE 的消融。收益来自路由还是来自新加的 encoder 层，拆不开（见 FAQ）。
  4. 表 3 没写任务和次数。数字与 Insert Plug 列吻合，只能推测。
  5. 平均值的口径。6 列平均，擦白板算了两次；“23.2%”是相对不接力基线的百分点差。
  6. 实现细节缺失。力的采样率和归一化、控制与推理频率、每块执行几步、Haction、是否全参数微调、MoE 是否有负载均衡损失，都没写。
  7. 基线的训练充分性。多任务下 π0-fast 两个版本全是 0%，基线可能没调好；各基线都只用约 50 条示范微调。
  8. 泛化范围有限。都是同一任务内换物体、高度、遮挡、扰动，没有跨任务、跨机器人或跨传感器。
  9. 示范本身不含“力的意图”。VR 遥操作的操作员感受不到力，示范里的用力方式是间接的。Tactile-VLA 正是用这个理由去自制带触觉的采集设备（见 §07）。
  10. 若干文字和图注笔误。§5.2 把 37.3% 标成了 w/ F；图 6(c) 的图注和正文不一致；专家编号 1–4 与 0–3 混用；图 10、11 有重复的行标签；§5.3 在 Object Gen. 1 上宣称领先，实际是与 π0-fast w/o F 打平。

和 Tactile-VLA：同期，同为 VLA，接法相反

两篇都是在 π0 式 VLA 上接力或触觉。Tactile-VLA 在相关工作里把 ForceVLA 归为“modality-specific routing”一类，并强调自己的主要贡献是证明 VLM 的隐空间里已有对物理交互的语义理解，少量示范就能激活，做到接触任务的零样本泛化（比如区分“用力插”和“轻轻插”）。

接法上，ForceVLA 刻意让力绕开 VLM；Tactile-VLA 刻意把触觉放进 VLM 的输入前缀，好让语言推理（CoT 变体）能用上触觉。解读这两者不矛盾：ForceVLA 自己的表 3 里，VLM 前的线性注入（55%）仍好于不接力（45%），崩掉的只是 VLM 前的 MoE。两篇的目标也不同，ForceVLA 追求成功率，Tactile-VLA 追求把语言里的力度语义落到力控上。

数据上，Tactile-VLA 指出普通遥操作的操作员没有力反馈，采到的策略自然不会依赖触觉，所以自制了带触觉的 UMI 采集设备。ForceVLA 用的正是没有力反馈的 VR 遥操作。

和 ME-Dex 1.0：触觉从“条件”变成“要预测的观测”

ME-Dex 的图 1 把“VLA 生成动作，部分设计再把当前触觉作为条件”列为第一类做法，并指出这类方法不联合预测未来的触觉、视觉和动作。解读ForceVLA 正属于这一类。ME-Dex 的核心主张是触觉和视频一样是对世界状态的观测，应当作为未来观测一起建模。

名字相近的“专家”含义完全不同：ForceVLA 的专家是一层里 4 个 MLP，按 token 学出路由；ME-Dex 的专家是按模态划分的 Transformer（Video / Tactile / Action），通过共享注意力相连。

和 Motus2：补上了“力的更新频率”

Motus2 的轻量触觉专家复用骨干的中间动作块和 KV 缓存：骨干只去噪一次到 σc，之后每个短子块执行前，用最新的触觉窗口完成最后一段去噪；同时用 flow matching 预测子块执行后的力窗口。ME-Dex 的相关工作也提到，Motus2 的注意力结构防止动作精修 token 看到加噪的未来力 token。

解读这正对应 ForceVLA 的一个空白：ForceVLA 的力只在每次整块推理时读一帧，块内开环。Motus2 把触觉更新拉到子块频率，而且不需要重跑整个骨干。

和 T-Rex：同样不让力进 VLM 输入，接到了去噪的最后一段

T-Rex 的主干（latent 专家和动作专家）完全不看触觉，触觉只进一个 0.62B 的独立专家，负责从 τ = 0.4 走到 0 的低噪声区间，而且一个 16 步动作块里用最新触觉重跑 4 次。它的基线里有一个“π0.5 + tactile”，把 10 指的 6 维力拼进状态输入，12 个任务平均从 π0.5 的 17 掉到 6。解读这和 ForceVLA 表 3 的方向一致：在 VLM 之前粗暴地融合力会伤到预训练表示，ForceVLA 的办法是挪到 VLM 之后，T-Rex 更进一步，挪到了去噪轨迹的末端。

两篇的力信号也相近：ForceVLA 是单帧 6 维末端 wrench，T-Rex 是每根手指的 6 轴 wrench（加一张形变图），并用 VQ-VAE 把 16 帧历史压成离散 token。

和 N₀-VTLA：同为 π 系 VLA，读“预测”而不是“当前”

N₀-VTLA 的相关工作把 ForceVLA 列为“以测量或估计的力为条件”的力感知变体。它自己的论点是：当前触觉只记录已经发生的接触，策略会比自己的接触事件慢一步。所以它不把当前读数交给动作专家，而是先预测接下来 50 步里触觉会变多少（潜变量 z），再让动作专家读 z。两篇都不让触觉进入 VLM 前缀，区别在于动作专家拿到的是当前的力（ForceVLA）还是对接触变化的预测（N₀-VTLA）。

和 N₀-TWAM：ForceVLA 式的“把当前力直接注入动作流”在世界模型里仍然有用

N₀-TWAM 的观测通路和 ForceVLA 的思路很像：当前触觉先转成三轴力图，编码后在动作头之前通过交叉注意力加到动作 token 上（输出投影零初始化）。它的相关工作把 ForceVLA 归为“把力反馈注入动作专家”的一类。去掉这条通路，NeoSim 从 49.4 掉到 29.6，UniVTAC 从 84.5 掉到 70.5。解读也就是说，即使模型已经在预测未来触觉，“把当前力直接给动作生成”这一步仍然有明显价值。

解读一条可以串起七篇的线：2025 年的两篇（ForceVLA、Tactile-VLA）解决“怎么把力/触觉接进预训练 VLA”，力是输入。2026 年分出两个方向：一是提高触觉的更新频率，T-Rex 在块内把去噪最后一段交给触觉专家，Motus2 沿用了这个机制；二是把触觉当成要预测的量，N₀-VTLA 在 VLA 里预测一个触觉变化潜变量，ME-Dex 和 N₀-TWAM 在世界动作模型里直接生成未来触觉，N₀-TWAM 还同时保留了当前力的注入。ForceVLA 的表 3 留下的经验（别粗暴改动预训练表示）在后面几篇里依然适用：它们都给触觉单独配了专家或通路，而不是把触觉塞进主干的输入。

08 · 术语表

术语表

展开 16 个术语
VLA
Vision-Language-Action。用预训练视觉-语言模型理解图像和指令，直接输出机器人动作的模型。
π0 / π0-base
Physical Intelligence 的 VLA。PaliGemma（SigLIP 视觉编码器 + Gemma 语言模型）做 VLM，另配一个动作专家，用 flow matching 生成连续动作块。本文的基座。
π0-FAST
用 FAST 动作 token 化把动作离散成 token、自回归生成的 π0 变体。本文基线之一。
Wrench（力旋量）
力 (fx, fy, fz) 与力矩 (mx, my, mz) 合成的 6 维量。本文用的是 TCP 上的估计值，表达在世界坐标系。
F/T 传感器
六维力/力矩传感器。论文局限部分提到的“高保真直接测量”指的就是这类传感器。
TCP
Tool Center Point，工具中心点。本文状态 st 是 TCP 位姿加夹爪宽度，动作是目标 TCP 位姿加夹爪宽度。
Contact-rich
接触密集的操作：插接、按压、擦拭、削切等，结果主要由接触力决定。
MoE
Mixture-of-Experts，混合专家。一组专家子网络加一个门控网络，每个 token 只激活其中少数几个。本文 E = 4，top-1。
Router / 门控
给每个 token 的每个专家打分的网络。本文是 Linear 2048 → 4。
Top-k 路由
只把 token 送给得分最高的 k 个专家，输出按门控权重加权。
负载均衡损失
MoE 训练中常用的辅助损失，防止所有 token 挤到少数专家上。本文未提及。
Flow matching
学习从噪声分布到数据分布的速度场，推理时数值积分得到样本。π0 用它生成动作块。
Action chunk
动作块：一次推理输出的未来 H 步动作序列。
Prefix / Suffix
π0 的两段 token：prefix 是图像和语言 token（VLM 处理），suffix 是状态和带噪动作 token（动作专家处理）。FVLMoE 的输出加在 suffix 上。
开环评估
在离线数据上前向模型，不与真实环境交互。本文的路由分析用的是这种方式。
Wilson 区间
二项比例（如成功率）的置信区间，小样本下比正态近似更稳。本页用它估计 20 次试验的不确定性。
