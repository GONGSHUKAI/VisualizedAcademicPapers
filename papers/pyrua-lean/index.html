Fewer Tokens, Better Action: GPT-6 Astra Robot Agents with 14% Higher Success Rate but 65% Fewer Tokens

规划器还是同一个 GPT-6 Astra，原语也还是同一套（含冻结的 VLA 策略），只换掉智能体和机器人之间的接口：不再「一次工具调用走一步，每步自动回传三张相机图」，而是让模型写一个 Python cell，在 cell 里串起几个原语、检查结果、就地重试，只把 print 出来的内容和主动要的图交回给模型。700 个仿真任务实例上成功率 63.1% → 71.7%；在两边都做成的实例上，LLM 调用少 49%，输入 token 少 65%。

做了什么

把 RPent（即 Harness VLA）的工具调用接口换成单个 python(code) 工具：机器人是一个 robo 对象，原语是它的方法，变量和自定义函数在同一回合的 cell 之间保留。原语实现、VLA、规划器、预算都不变，比的是「接口整体」。v2 新增两部分：RoboDojo 上一个完全不用 VLA 的版本，以及用 GRPO 训练的 4B 开源规划器。

放在 Harness 里看

归入（1）总体设计。它改的不是某一个环节，而是模型和机器人之间的交互单位。一个 cell 同时决定这一步看什么（上下文）、什么留在运行时变量里（状态）、几个原语怎样带条件串起来（执行结构）、失败在哪一层重试（反馈）。

结果

四组基准成功率都升（+5.0 到 +11.0 个点），代码独做成 96 个实例、工具调用独做成 36 个。两边都成功时，每回合 LLM 调用 17.0 → 8.7 次，token 788k → 276k，费用 $1.63 → $0.74。RoboDojo 一个评测种子平均 SR 51.6%（榜首 VPP2 32.3%）。4B Coder 在训练没见过的 655 个实例上 18.8% → 44.1%。

最该留意的

省 token 的数字只在两边都成功的 406 个实例上算，LIBERO-PRO 占了大头；算上失败回合，RoboCasa365 atomic 上两者每回合花费几乎一样（$0.94 对 $0.96）。第 3 节两个智能体都能读基准的成功标志 robo.done，代码还拿它控制重试。每个实例只跑一次，没有计时；RoboDojo 每回合约 12.7 分钟、$2.4。

问题 · §1 · 附录 A

工具调用的账单：每走一步，整段历史再读一遍

VLM 智能体操控机器人，常见做法是工具调用：模型挑一个原语（移动、分割、调用 VLA 抓取），执行完把结果交回，再决定下一步。论文指出这里有两笔开销。第一，依赖上一步结果的操作，一般每一步都要一次新的 LLM 调用。第二，中间结果留在对话里，之后每次调用都要再处理一遍；RPent 这类系统还会在每次运动后自动回传多张相机图。于是需要反复定位、移动、恢复的任务，推理开销很大，即使每个原语本身都可靠。

论文的问题是：LLM 智能体能不能把原语组合起来，既可靠地完成任务，又通过「有选择地看」和「管理上下文」少用 token？

解读为什么 token 随调用次数超线性增长

每次调用的输入是系统提示、之前的全部对话和新结果。表 10 的累计值逐行相减（我们算的）：工具调用第 1 次读入约 20k，到第 20 次每次读入约 77k；代码 8 次调用每次 22–32k。少一次调用，省下的不只是这次新增的内容，还有又一遍完整历史。所以论文后面把 token 比拆成「调用次数比 × 每次调用 token 比」，结论是前者占大头（见省在哪）。

方法 · 接口与执行模型 · §3.1–3.3 · 表 1

机器人是一个 Python 对象，一次 LLM 调用写一个 cell

执行模型

一个 robo 对象，一个 python(code) 工具

原语是 robo 的方法，返回结构化结果（物体位置、运动是否到达）。智能体拿到一份 API 参考，只通过 python(code) 交互：写一个 cell，运行时执行，返回的反馈决定下一次调用。GPT-6 Astra 每次调用写一个 cell。

状态

持久命名空间，只在回合内

变量和自定义函数在同一回合的 cell 之间保留。评测关闭跨回合记忆。未捕获的异常终止当前 cell 并把 traceback 交回 LLM，异常之前赋值的变量仍在，下一个 cell 可以接着修。

观测

只交回点名要的

原语结果留在运行时里，不逐个进对话。代码 print 的内容和 robo.show(camera) 要的图在指定位置记录下来，cell 结束时一起返回。

运行时的闸

任务已成功就停，2 小时看门狗

每个作用于机器人的原语执行之前，若任务已经成功，运行时直接终止 cell。外部看门狗在 2 小时回合上限时打断正在执行的原语并停掉规划器。cell 本身不限时：Codex CLI 300 秒后返回超时但不取消 cell，后面的 cell 排队。

上下文

只管新进来的，不删历史

两个智能体都跑在 Codex CLI 里，保留完整对话，接近 272k token 时才把前半段压缩成摘要。PyRUA-Lean 控制的是哪些新内容进入上下文。

解读「同样的原语」同样到什么程度

动作和感知原语确实是同一份实现。不同的有三处：观测（每次运动后三张图，还是代码点名才给）、世界坐标的形态（逐点 back_project，还是一次拿整张 world_map 数组）、控制流（一次调用一个工具，还是任意 Python）。论文明说比较的是「接口整体」，不拆这三项。第二处差别给了代码一种工具调用拿不到的数据形态：附录里那些「自己做感知」的 cell（拟合平面、求主轴、三点定圆）都是在这张点云数组上算的。

疑点「65% fewer tokens」是哪个口径

        
标题和摘要里的 65% 是 406 个两边都成功的实例上的合并均值（788k → 276k），LIBERO-PRO 占其中 164 个，且每回合 token 最多。按表 2 和各组两边都成功的实例数加权（我们算的），去掉 LIBERO-PRO 后合并 token 比约 1.8×，即少约 44%。费用的差距更小：缓存输入只收十分之一的价，工具调用反复读的历史大多命中缓存，所以合并费用比是 2.2×（便宜约 55%），低于 token 比 2.9×。算上失败回合，RoboCasa365 atomic 上每回合 $0.94 对 $0.96，代码略贵：失败回合两边都接近 40 次调用的上限，而代码每次调用的输入更多。论文在附录 D 和 §3.8 交代了这些数字。

第二部分 · RoboDojo · §4 · 表 4–7 · 附录 F–G、I（v2 新增）

      
不用 VLA，只用几个几何原语，RoboDojo 平均成功率 51.6%

      

        
第 3 节固定规划器和原语、只换接口；这一节换个问题：在一个为预训练策略设计的公开基准上，这个接口能把冻结的 LLM 带多远？之前 Zhang 等人测过 GPT-6 Astra 每次调用直接给一个末端目标（direct control），从 RGB 图像上不经任何机器人训练就拿到 22.5%，高于当时榜上所有预训练策略，但需要精度的任务几乎为零。本节用同一个 LLM、同样的 RGB 观测，换成 PyRUA-Lean 来操作。

        
    
          
  • 基准：RoboDojo 仿真赛道，双臂 ARX-X5 工作台，42 个桌面任务分五个能力维度：Generalization 12、Precision 8、Long-Horizon 8、Memory 6、Open 8。每个评测种子 50 个公开布局（Generalization 任务一半标准场景、一半随机外观），一个种子共 2,100 个回合。报两个指标：SR（完全成功的比例）和 Score（过程奖励均值 × 100，按阶段给部分分）；任务在维度内平均，Average 是五个维度的等权平均。用官方评测代码（commit cb2a37d），智能体打包成一个 XPolicyLab 策略，和其他参评策略一样由评测客户端发观测、执行动作、判成功。只评了种子 0。
    • 
          
  • 智能体：GPT-6 Astra、高推理强度，权重不动，不看示范。只通过 python(code) 操作，换成作者自己写的极简智能体循环（不再用 Codex CLI）；每回合 100 次 LLM 调用预算（只数执行了 cell 的调用）、图像按需、不带跨回合记忆、每次调用最多 8,192 个输出 token；某次调用没给代码就提醒一次，每回合最多 20 次。

运动（原文表 4）
move_to · set_gripper · home
move_to(xyz, arm, gripper, pitch, yaw, roll, path) 把一只手的抓取点送到某个位姿，库里解逆运动学，路径可选抓取点直线或关节空间摆动，报告是否到达，或附近哪些位姿可达。set_gripper 走完整个夹爪行程，报告手指是否停在了东西上、开口多宽。home 回初始关节角。

        
感知与观测（原文表 4）
locate · segment · back_project · show …
locate(text, camera) 用 SAM 3 在一个相机里分割点名的物体，到其他相机里找同一物体，从这些视角测出中心、顶面、占地和横跨窄边的抓取朝向，并报告几个相机一致（单个相机测不出高度）。另有分割、像素反投影到物体或桌面、状态、取图、相机标定。

      

      

        
库里没有 pick、place 或 grasp 原语：一次抓取是几行代码，定位物体、带着测得的朝向移到上方、沿直线下降、合拢夹爪并检查报告的开口。作者说只有当程序无法用已有原语拼出某个功能时才加新原语。不用 VLA 是有意的：VLA 是随机原语，同一次调用这回成功下回失败，第 3 节里有些「只一边做成」的实例差别只在同一个 VLA 调用的成败；几何原语报告测到或到达了什么，程序可以逐步检查，结果衡量的就是 LLM 写的程序。

      

      

        
不读深度，locate 怎样测出三维位置（开源代码 hosts/robodojo_sight.py，commit ffad6d4）

        
论文正文只用一句话带过，代码里写得很清楚。前提是相机位姿全部已知：头部相机固定（焦距 288 px，位于 (0, −0.41, 1.308) m，俯视 60°）；腕部相机固定在末端连杆上（末端前 8.5 cm、上 5.1 cm，比夹爪指向再低 30°），末端位姿就在每步的机器人状态里，所以腕部相机的外参随时可算。这些常数和桌面高度 z = 0.765 m 一样，是作者从仿真器里读一次写死的。于是每个像素都是一条已知射线，再加一条假设：物体立在桌面上。

        
    
          
  1. 一个视角给出「影子」。SAM 3 按文字分割出掩码，掩码像素的射线与桌面相交，得到物体在这台相机看来投在桌面上的影子。物体占据相机和影子之间的某块空间，但读不出高度：矮而深和高而浅的东西影子一样。
    2. 
          
  2. 按高度枚举实体。在桌面网格上以 2 mm 一层、最高 36 cm 扫高度 h（先隔层粗扫，再在最好的附近细扫）。每个 h 有两种读法：直立棱柱（影子里那些「柱子升到 h 仍落在掩码内」的格子，对盒子、罐子就是精确的占地）和悬挂体（h 处的点在掩码内、往下尽量延伸，对应碗这类上宽下窄的东西，只有明显更好时才选它）。
    3. 
          
  3. 第二个视角定高度。到另外两台相机里找同一物体：用同样的文字再分割一次，同时把第一张掩码中心那条射线在 0.4、2、5、10、18 cm 高处的点投影过去，作为 SAM 3 的点提示。每个候选实体投影进第二个视角，和那里的掩码算 F1，最高的读法和高度胜出；F1 低于 0.55 的掩码视为别的东西。机器人自己的手指和另一只手臂按运动学画出轮廓，那些像素不计分。
    4. 
          
  4. 输出。中心、顶面高度、占地的最小外接矩形、长轴方向、横跨窄边的抓取 yaw，以及几个视角一致（views）。只有一个视角时，取仍能覆盖整张掩码的最高棱柱当高度，盒子、罐子接近，碗、杯会错，结果里注明「高度是猜的」。同一个提示词一旦有两视角一致的高度，之后的调用会沿用。
    5. 
        

        
所以工具说明教给 GPT-6 Astra 的抓取套路是：先用头部相机 locate，移到物体上方 9 cm、夹爪朝下，再用腕部相机 locate 一次（docstring 写俯视时精度 1–2 mm），转到 grasp_yaw 再下降。加深度的配置只把这一步换成读掩码下的深度像素，同一种子上 SR 51.6% → 52.4%，多视角几何丢掉的精度不多。

关键 insight

      

        
1. 交互单位决定了成本结构
每次 LLM 调用都要重读历史，所以总 token 大致随调用次数超线性增长。把依赖链放进一个 cell，省掉的是整段历史的重读。LIBERO-PRO 上 2.55× 更少的调用乘上 1.76× 更小的每次输入，得到 4.48× 的 token 差。

        
2. 「看什么」得和「怎么做」一起设计
只把工具调用改成按需要图，成功率从 83.0% 掉到 68.5%，token 一点没省。代码能省，是因为它在同一个 cell 里决定了做完什么再看、什么情况下才看（20% 的 cell 只在任务没完成时才看）。

        
3. 代码让 LLM 补上原语库里缺的东西
拟合壶盖平面把倒下的壶扶正、三点定圆沿弧线拉柜门、8 mm 一步的带检查下降：这些都不是工具列表里的功能，是 cell 用 NumPy 和已有原语现场搭出来的。没有 VLA 时代码的优势更大（RoboTwin 2.0 +26.0 个点），原因也在这里。

        
4. 接口可以学
只用 45 个实例、0/1 奖励，4B 模型在三个基准的未见实例上从 18.8% 到 44.1%。学到的主要是使用协议（一次一个 cell、看结果再写），这正是接口本身的价值能迁移的原因，但它离 GPT-6 Astra 还很远。

      

      
容易误解的地方

      

        
    
          
  • 「65% fewer tokens」不等于便宜 65%。它是两边都成功的实例上的 token 均值，LIBERO-PRO 权重最大；费用口径是便宜约 55%（2.2×），全部回合口径下 RoboCasa365 atomic 两边一样贵。
    • 
          
  • 第 3 节不是「零特权」。两边都能读基准的成功标志，代码用它重试、运行时用它截停 cell。RoboDojo 一节才是不给成功信号的设定。
    • 
          
  • RoboDojo「不用 VLA」不等于没有学习组件。GPT-6 Astra 和 SAM 3 都在，原语库和操作说明是作者为这个工作台写的。
    • 
          
  • 这不是和 Code as Policies 一类方法的对比。基线是工具调用，不是一次性生成整段程序的方法；论文没有和 CaP-X 等代码智能体做实验对比。

FAQ

      
为什么不直接让工具调用少返回一些图？
作者试了（表 14）：工具不再自动带图、想看就调相机工具，LIBERO-PRO 成功率 83.0% → 68.5%，主动放弃和预算用完都变多，三者都成功的实例上调用 19.9 → 22.8 次，token 不变（1.07M）。看图需要多一次调用，于是省下的图被多出来的调用抵掉了。

      
代码智能体写出卡死或乱动的 cell 怎么办？
论文给出的保护只有三层：每个动作原语执行前检查任务是否已成功，成功就终止 cell；外部看门狗在 2 小时回合上限时打断；未捕获异常终止 cell 并返回 traceback。cell 本身不限时，Codex CLI 300 秒后只返回超时、不取消 cell。原语（如 move_to 的 step_clip、max_steps）带自己的参数限制。论文没有统计危险动作或碰撞，也没有真机实验。

      
一个回合要多久？
第 3 节不计时，论文说共享网关上单次调用延迟波动太大，所以只数调用。RoboDojo 一节给了：每回合约 12.7 分钟，25.7 次 LLM 调用。作为对比，MotorMind 在 LIBERO-PRO 上每回合约 223 秒，微调 VLA 约 6 秒。

      
为什么 RoboDojo 上要单独写一套原语，而不用 RPent？
第 3 节用的是 RPent 为 LIBERO-PRO、RoboTwin 2.0、RoboCasa365 准备的机器人栈。RoboDojo 是另一个工作台（双臂 ARX-X5），作者为它写了自己的库，并有意不放 VLA，让结果只反映 LLM 写的程序。代价是没测「加上 VLA 原语」会怎样，这一点论文列为局限。

    


    

      
局限与疑点

      
作者承认的，和我们读出来的

      

        

          
论文自己提到的

          
    
            
  • 接口对比只用了 GPT-6 Astra、RPent 的机器人栈和原语库、仿真，每个实例每边一次；换规划器、换原语、重复运行的方差、真机都没测。
    • 
            
  • 比较的是完整接口，没有把原语组合、持久状态、选择性反馈的作用分开；token 分解是记账，不是因果；按需要图的实验也没量化选择性反馈在 PyRUA-Lean 内部的贡献。
    • 
            
  • token 预算曲线是对已录轨迹的事后截断。
    • 
            
  • 代码独做成的 96 个里，52 个是工具调用预算用完，44 个是它自己结束；后者里有的只是 VLA 一边成功一边失败，增益不能全归给恢复逻辑。
    • 
            
  • 效率增益依任务结构而定；算上失败回合，RoboCasa365 atomic 上两者费用相当。
    • 
            
  • RoboDojo：没量感知原语与程序各贡献多少；失败集中在没有接触反馈或配合很紧的任务，没逐回合分析；没测加 VLA；成本高，只评两种配置。
    • 
            
  • Coder：一个尺寸、一次训练、一个基准的 45 个实例、只用成功奖励；离前沿模型很远；没在 RoboDojo 的无 VLA 原语上测过。

我们读出来的

          
    
            
  • 疑点第 3 节两边都读基准成功标志，代码的重试和运行时截停都依赖它；绝对成功率不能直接搬到没有判定器的场景。
    •

为什么归入（1）总体设计

      

        
在 Harness for Robotics 专题里，（1）总体设计收的是把整套 harness 当作一个系统来设计的工作：智能体用什么接口驱动机器人、观测和执行结果怎样回到模型、经验怎样沉淀。PyRUA-Lean 只换了一样东西，即交互单位从「一次工具调用」变成「一个可执行 cell」，但这一换同时改动了后面四类的每一个环节：

        
    
          
  • （2）上下文架构：cell 自己决定交回哪几行文字、哪几张图；20% 的 cell 只在任务没完成时才看。
    • 
          
  • （3）持久状态：位置、偏移、自定义函数留在 Python 命名空间里，不进上下文，除非被 print；只在回合内，跨回合记忆关闭。
    • 
          
  • （4）结构化执行：依赖链、循环、带检查的下降写在 cell 里，LLM 只在 cell 边界重规划。
    • 
          
  • （5）评估与反馈：每个原语返回到达与否、夹爪开口等实测值，cell 内就地检查与重试；异常把 traceback 交回模型。
    • 
        

        
论文也承认这几样拆不开、没单独消融。这正是它属于「总体设计」而不是其中某一类的原因。

  • 和 ASPIRE（同属（1））：两篇都让 LLM 通过代码驱动机器人，但把 LLM 放在相反的位置。ASPIRE 把 LLM 移出运行回路：在调试种子上反复执行、读逐原语轨迹、修程序、做进化搜索，把验证过的修复写进跨任务技能库，最后只部署程序。PyRUA-Lean 把 LLM 留在回路里：每个回合现场写 cell、现场读结果，不留任何跨回合经验，关注的是每回合的调用次数和 token。PyRUA-Lean 在相关工作里把 ASPIRE 列为互补方向，并把「跨回合复用验证过的程序」写进未来工作。两篇的 LIBERO-PRO 数字不能横比：任务子集、是否用 VLA、是否有成功标志、是否有逐任务调试都不同。
    • 
          
  • 和 MotorMind（（4）结构化执行）：两者都是冻结的前沿 LLM 一步步驱动原语。MotorMind 一次提议一个没有分支的动作批次，检查交给单独的 Verifier 和并行的 Monitor，每次检查都是一次 VLM 调用；PyRUA-Lean 把检查写进代码（if approach.reached and not robo.done），读原语的实测返回值，不花额外调用，但依赖原语会报告结果（第 3 节还依赖成功标志）。MotorMind 的对比里也有 RPent（Harness VLA），用 Qwen 规划器零样本基础 31.7%、扰动 28.8%；本文 RPent 换成 GPT-6 Astra，在另一个 LIBERO-PRO 子集上到 83.0%，规划器的差别比接口的差别大得多。
    • 
          
  • 和 HiMe（（3）持久状态与记忆）：HiMe 在策略之外维护一份图文记忆，由 GPT-4o 在子任务交接时增改删，再经一句子目标交给 π0.5。PyRUA-Lean 的回合内状态是 Python 变量，存的是精确数值（碗的世界坐标、抓取偏移），除非 print，否则不经过上下文。一个是给语言模型读的记忆，一个是给程序读的状态。
    • 
          
  • 和 τ₀-VLA（（5）评估与反馈）：τ₀-VLA 在承诺前用世界模型想象后果再打分；PyRUA-Lean 在每个原语之后检查实测结果，便宜且精确，但只能事后补救。摩卡壶那个实例就是事后补救：壶已经倒了，代码现场算出倾斜再扶正。

术语表

      
读这篇会遇到的词

      
展开术语表
        

          
tool calling
工具调用：模型每次输出一个（或一批）工具调用，执行结果作为新消息交回，下一次调用再决定做什么。

          
code cell
本文中一次 python(code) 调用执行的一段 Python，类似 notebook 的一个单元格。

          
robo
暴露给代码的机器人对象，原语是它的方法，如 robo.move_to、robo.segment、robo.show、robo.done。

          
persistent namespace
持久命名空间：同一回合内各 cell 共享的变量与函数，回合结束即清空。

          
selective observation
选择性观测：只把代码 print 的内容和 robo.show 点名的相机图交回模型。

          
RPent / Harness VLA
基线系统（arXiv 2607.08448）：记忆引导的智能体框架，把冻结 VLA 与解析原语作为工具；本文用它的机器人栈和原语实现，并关闭跨回合记忆。

          
jointly solved
两边都做成的实例，本文的 LLM 调用、token、费用对比都在这个子集上算（406 个）。

          
task instance
任务 × 环境种子；本文 140 个任务 × 5 个种子 = 700 个实例。

          
LLM-call budget
每回合允许的 LLM 调用次数（40，composite 100），限制的不是原语执行次数。

          
cached input
命中提示缓存的输入 token，标价是普通输入的十分之一；本文的 token 计数包含它。

          
Codex CLI
第 3 节两个智能体运行的命令行代理环境，保留完整对话，接近 272k token 时压缩。

          
SR / Score
RoboDojo 的两个指标：完全成功的回合比例；过程奖励均值 × 100，按阶段给部分分。

          
direct control
GPT-6 Astra 每次调用直接给一个末端执行器目标的设定（Zhang 等人的 RoboDojo 早期评测）。

          
GRPO
group relative policy optimization：同一实例的一组 rollout 内归一化奖励作为优势的策略梯度方法。

用 GRPO 在 45 个 LIBERO-PRO 实例上训练的 Qwen3.5-4B 规划器。
