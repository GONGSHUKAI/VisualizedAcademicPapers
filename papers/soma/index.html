SOMA

Spatial Memory for Out-of-Vision Manipulation in Vision-Language-Action

给 GR00T N1.5 式的 VLA 外挂一层物体级空间记忆：目标不在视野里时，可动头部按固定轨迹扫一圈，用 YOLO-World 检测、DINOv3 取外观、VGGT 抬到 3D，每个物体压成一个记忆 token；操作中用头部新画面做门控 EMA 刷新，再让 VLM 的 token 对记忆做交叉注意力，结果送进 DiT 动作头。5 个涉及视野外物体的真机抓放任务，每任务 20 次，各阶段平均成功率 28.3%，GR00T N1.5 约 18%。

  • arXiv 2605.22283v1
  • v1 2026-05-21 · arXiv 注明已被 ICML 2026 接收
  • arXiv · 代码：论文称“即将发布”

做了什么

三个组件：Spatial Memory Construction（扫描建图）、Dynamic Memory Refinement（α = g·s 的门控 EMA 刷新）、Contextual Memory Retrieval（VLM token 作 query 的交叉注意力）。记忆是一组物体 token：m = Φmem(DINOv3 外观) + Φpos(VGGT 3D 框)，384 维。

数据与配方

自研人形平台：两条 7 自由度 Realman 臂、2 自由度云台头、头和双腕各一个 D435。VR + 外骨骼遥操作，5 个任务各 400 条示范（约 15.5 小时）。以 GR00T N1.5 为基座，除 VLM 语言解码器外全部训练，32 张 H200、30k 步。

结果

真机 5 任务各阶段平均 28.3%；按图 4 算，GR00T N1.5 18.3%、StarVLA 18.2%、SpatialVLA 15.5%。头部搜索转角、抓取次数等 5 项行为指标比 GR00T 少 40–60%。全可见的 RoboCasa GR1：Full 数据 49.3 vs GR00T 45.9；SimplerEnv Visual Matching 平均 63.2。

最该留意的

真机绝对成功率低（最难的双臂任务放置阶段 10%，即 2/20），每任务 20 次、无方差。表 2 消融的数字和“20 次 × 阶段平均”的粒度对不上；附录 GR1 逐任务表与类别均值多处算不拢；仿真两套基准都是全可见，没有测视野外能力。

问题 · §1

指令里的东西不在画面里，VLA 就没有依据

多数 VLA 在固定视角的桌面上训练：一个静态相机或第三人称视角，标定简单、状态估计稳定、数据好采。论文指出这里藏着一个视野绑定假设（view-bound assumption）：决策时，指令提到的物体一定在当前相机画面里。目标一旦被遮挡或在视野外，感知—动作回路就断了，策略没有任何上下文去推断它在哪。

现有的两条补救路线，论文认为都不够：

  • 靠模型内部的空间推理猜。RoboBrain、Galaxea G0、AgiBot 等用学到的空间先验推断看不见的目标。但现有 MLLM 只有在画面里有部分证据或相关线索时才推得准，目标完全在视野外时空间估计迅速变差（引 VSI-Bench）。没见过、或者见过但没存下来的东西，模型再大也补不回来。
  • 装可动相机去找。ViA、ActiveUMI 用可动相机暴露未见区域，但它们不看指令（instruction-agnostic），底层是 Diffusion Policy，没有持久的空间记忆。MemoryVLA、MemER 这类记忆设计存的是最近的观测或关键帧，服务于短时推理，也不保存当前视锥以外的空间信息。

论文的结论是需要两样东西同时具备：能拿到当前视野以外的空间证据（可动头部），以及把证据存进一个持久的场景表示（空间记忆）。

解读这篇的 harness 改的是“记什么”，但先要改“看什么”

SOMA 的记忆不是从策略看过的画面里被动攒出来的。它先主动扫一遍场景，把视锥外的物体写进记忆，再让策略在操作时读。所以它同时动了两处：扫描阶段决定记忆里有什么，检索阶段决定策略每一步从记忆里拿到什么。表 2 的消融正好把这两件事拆开（见结果部分）。

方法 · 全局 · §3 · Figure 2

扫描 → 记忆 → 刷新 → 读出 → DiT

推理时的一个回合按论文 §3 和 §4.2 的描述是这样走的：

  1. 触发。一个轻量检测器检查指令里的目标在当前视野里能不能定位到。能，就不扫描；不能，就启动扫描。
  2. 扫描建图。头部沿预先定义的轨迹转动，采一段多视角视频，每 N 帧取一帧，生成 overview memory 𝓜0。
  3. 每一步。输入当前三路相机 otc（c ∈ {l, r, h}：左腕、右腕、头部）、指令、机器人状态、加噪动作序列。只有头部画面 oth 被拿来刷新记忆，得到 𝓜̂t。
  4. 读出与出动作。VLM 的视觉语言 token 对 𝓜̂t 做交叉注意力得到 Xboost，和原始视觉语言 token、状态、加噪动作一起进 DiT，动作解码器输出长度为 H 的动作块（H 未披露）。

GEOMETRY

VGGT

估计每帧的相机位姿和粗略场景几何。VGGT 在同一个场景级坐标系里给出所有帧的位姿，论文直接把它当作全局参考系，所有 3D 框都表达在这个系里。

SEMANTICS

YOLO-World

APPEARANCE

DINOv3

给出特征图 F(i) ∈ ℝH×W×C。用 2D 框裁出对应区域，空间平均池化，得到实例外观向量 f(i)j ∈ ℝC。

  • 抬到 3D。每个 2D 检测借 VGGT 的几何先验抬成 3D 框 b(i)j ∈ ℝ8×3（8 个角点）。
  • 跨视角关联。同一物体会在多帧里出现，同类的不同物体也要分开。做法是按类别分组，组内用 DINOv3 外观的余弦相似度加 3D 框的空间一致性算联合相似度，超过阈值就合并，外观特征和 3D 几何取平均。得到 NI 个全局实例：𝓕 = {fk}、𝓑3D = {bk}、𝓒3D = {ck}。

解读记忆的形状：NI 个 384 维 token，与时间长度无关

Φmem 的输入是 384 维，说明 DINOv3 的特征宽度 C = 384，对应 ViT-S 一档（论文没写用哪个变体）。图 8 里去掉 DINOv3 只省约 114 MB 显存（7966 → 7852 MB），也和小模型一致。记忆的大小由场景里的物体数决定：一个桌面几个物体，就是几个 token。这和 MemoryVLA 那种按时间步存 token 的记忆很不一样，后者随回合变长而增长，需要合并来控制容量。

方法 · ② Dynamic Memory Refinement · §3.2

新观测要不要写进去，由两个门的乘积决定

操作过程中物体会被移动、遮挡或新出现。每一步，当前头部画面 oth 过同一条流水线，得到当前记忆 token 𝓜t = {mtj}，其中 mtj = Φmem(ftj) + p̄cjt。然后和上一时刻的记忆 𝓜t−1 做实例级关联：

  • 只在同类条目里找，判据与扫描建图时相同（外观+几何）。
  • 一对一：每个观测最多匹配一个记忆条目，每个条目每步最多被一个观测更新。
  • 匹配上的，算两个分数再做 EMA：
stkj = σ(Φsim([mt−1k − mtj])),   gtkj = σ(Φfuse([mt−1k, mtj]))(1)
αtkj = gtkj · stkj,    mtk = αtkj mtj + (1 − αtkj) mt−1k(2)
  • 没匹配上的新观测追加为新条目。
  • 没被观测到的旧条目保留，用来应对暂时遮挡和部分可观测。

结果记为 𝓜̂t = {m̂tk}，共 NMt 个条目。整个过程没有删除操作。

疑点公式和附录表 6 对不上的三处

  • Φsim 的输入维度。公式里 Φsim 只吃差向量 [mk − mj]（384 维），表 6 却写 LN(3×384)、Linear(1152→768)，输入是三个 384 维向量的拼接，可能是 [mk, mj, mk − mj]，正文没说。
  • s 和 g 不是标量。表 6 里 Φsim 和 Φfuse 的最后一层都输出 384 维（再接 LayerNorm），过 sigmoid 后是 384 维向量。如果按表 6 实现，α 是逐通道的门，“语义相似度分数”这个说法只是比喻。另外整个训练只有动作损失，s 并没有被监督成“相似度”。
  • 位置项的记号变了。§3.1 用每个实例自己的 pk，§3.2 写成 p̄c。tex 源码里被注释掉的早期版本把 p̄c 定义为同类别所有框的平均位置编码；正式版说它是“由该实例估计 3D 位置得到的位置编码”。如果实现里真是按类平均，同类的多个杯子会共用一个位置，这和“类内区分实例”的目标矛盾。

方法 · ③ Contextual Memory Retrieval · §3.3 · 附录表 6

没有“选中目标”这一步：VLM 的所有 token 对全部记忆做注意力

VLM 输出的视觉语言 token Xvl = {xi}i=1…Nq 当 query，刷新后的记忆 𝓜̂t 当 key/value。记忆 token 先经对齐 MLP 投到 VLM 的特征空间：

m̃tk = Φalign(m̂tk),    Xboost = softmax( Q K⊤ / √C ) V,   Q = Xvl,  K, V ← 𝓜̃t§3.3
QUERY

Nq 个 VL token

来自 VLM（框架图里三路相机画面和指令一起进 VLM），包括图像 token 和指令 token。Xboost 的长度和 query 一样是 Nq：每个 VL token 都被“补”上记忆里的空间信息，而不是检索出几条记忆。

KEY / VALUE

NMt 个记忆 token

Φalign：LN 384 → 384→768 → GELU → 768→dVLM → GELU → LN。dVLM 的数值没写。附录的 Memory–Token Transformer 是 3 层、32 头、每头 64 维、dropout 0.2。

INJECT

进 DiT 当全局上下文

Xboost 作为空间—语义先验注入 DiT 块；原始 VL token、机器人状态、加噪动作嵌入照常进 DiT。论文说 Xboost “调制 token 间的交互”，具体是拼进交叉注意力的 K/V 还是别的方式，未披露

读出模块怎么做（附录表 10 · Retrieval Module）

GR1 Full 数据，平均成功率。Concat = 把感知 token 和记忆特征直接拼接；Light / Middle / Heavy = 2 / 3 / 4 层交叉注意力。

论文说读出性能“和模型容量强相关”，但数字并不单调：2 层（42.8）比直接拼接（45.6）还低，4 层（44.4）又比 3 层（49.3）低近 5 个点。更稳妥的读法是：3 层这个配置在这次评测里最好。

疑点交叉注意力还是自注意力

正文和表 10 图注都说是交叉注意力（cross-attention），附录表 6 却把这个模块写成“Self-Attention Transformer (3 layers)”。如果是把记忆 token 和 VL token 拼在一起做自注意力，记忆 token 之间、VL token 之间也会互相看，和公式里的单向读出不是一回事。另外公式用 √C 缩放，而多头实现里应是每头维度 64。

      定性结果

      读懂它

      这篇真正说明了什么

      关键 insight

      1. 空间记忆可以按“物体”而不是按“时间”组织

      SOMA 的记忆是 NI 个物体 token，每个绑定一个 3D 框。它回答的是“东西在哪”，不是“刚才发生了什么”。容量随物体数增长、不随回合长度增长，也就不需要 MemoryVLA 那样的合并机制。代价是它对“状态”无感：失败分析里 24% 的仿真失败是分不清抽屉开关。

      2. 扫描只是取证，存下来并持续刷新才有用

      表 2：只扫描、把那一帧喂给反应式策略（18.5）几乎没有增益，和图 4 里 GR00T 的 18.3 相当。扫描建图 +4.3，持续刷新再 +4.2。换句话说，主动去看本身不够，看到的东西要进一个能被反复读的结构。

      3. 现成感知模型做“记什么”，VLA 只负责“怎么读”

      YOLO-World、DINOv3、VGGT 都是冻结的外部模块，训练时离线跑完。真正训练的是几个小 MLP、门控和 3 层注意力。这让记忆的质量上限受感知模型约束：44% 的仿真失败来自 VGGT 的几何噪声。

      4. 全可见的仿真增益主要来自一类任务

      GR1 上 SOMA 对 GR00T 的平均优势和消融里完整模型的优势，都主要落在容器交互这一类。下图把这一类拿掉后重算消融平均。

      容易误解的地方

      • “检索”不是搜索。没有显式选出目标物再去找的步骤；所有 VL token 对全部记忆 token 做软注意力，取哪条靠学到的权重。仿真里 32% 的失败恰恰是注意力激活了无关条目。
      • 扫描不是学出来的主动探索。扫描沿预定义轨迹走，由一个检测器判断“目标不可见”来触发。操作中头怎么动是策略输出的（解读：遥操作数据里操作员用手柄按键控制头部，行为指标统计的就是这部分头部运动，但论文没有列出动作空间的维度）。
      • “40–60% 的行为改善”只对比了 GR00T N1.5。StarVLA、SpatialVLA 没有行为指标。
      • 仿真结果不测视野外能力。GR1 和 SimplerEnv 都是全可见，记忆从第一帧构建，没有扫描。论文把它们定位为“常规可见条件下记忆设计依然有益”。
      • 真机“最高成功率”是相对的。SOMA 平均 28.3%，意味着大约十次里成功三次左右。

      FAQ

      物体在视野外被挪走，记忆会怎样？

      按 §3.2 的规则，没被观测到的条目原样保留，所以记忆会一直指向旧位置，直到头部再次看到这个物体。看到之后，如果按“同类 + 外观 + 几何”的判据匹配上，就用 α = g·s 做 EMA，逐步移到新位置；如果几何差太多没匹配上，会作为新条目追加，旧条目仍在，记忆里就有了一个过时的副本。论文在局限里承认“陈旧或错误的记忆可能危及安全”，提出记忆过期、重新扫描触发等缓解办法，但没有实现。真机的 5 个任务里也没有“趁机器人不看时挪动物体”这种扰动。可以在上面的沙盘里试。

      操作阶段的单帧怎么放进扫描时的全局坐标系？

      论文没说。§3.1 说 VGGT 对扫描序列给出一致的场景坐标系，并把它当全局参考系；§3.2 说当前头部帧“过同一条流水线”。单帧跑 VGGT 只能得到相机坐标系下的几何，要和扫描坐标系对齐，需要联合推理、配准，或者用头部关节角算外参。三种做法论文都没提到。

      为什么不直接用深度相机？

      表 13 的对比：RGB-D + OpenCV 融合 22.6%，VGGT 27.3%，延迟 0.18 s vs 0.21 s。论文的解释是多视角点云配准会累积深度噪声和错位，VGGT 的跨视角几何更一致。这是一次单配置对比，没有试别的配准方法。

      记忆在 GR00T 里接在哪？

      在 VLM 输出和 DiT 动作头之间。VLM 的 token 先对记忆做 3 层注意力得到 Xboost，Xboost 作为额外的全局上下文送进 DiT，原始 VL token 照常送入。GR00T 的 VLM 本体不看记忆。训练时除了 VLM 的语言解码器，其余部分都更新。

      为什么 GR1 上的记忆也有用，明明什么都看得见？

      论文的解释是显式场景表示 + 指令条件的读出提供了更结构化的归纳偏置。附录图 10 的图注补了一点：GR-1 的手臂、手、腰会带着头部相机大幅晃动，视角不稳，记忆提供了一个跨帧稳定的物体表示。不过上面的分析显示，增益主要集中在容器交互一类，其余类别和 GR00T 互有高低。

      局限与疑点

      作者承认的，和我们读出来的

      论文自己提到的（附录 D.7、D.8）

      • 扫描假设场景准静态、时间短；实例关联和融合用全局固定阈值。完全动态的场景、更大的自运动、密集杂乱需要实时跟踪、基于置信度的重扫和逐 token 的几何置信度；匹配判据应该学出来而不是手调。
      • 残余失败更多来自“头还在动时把空间线索变成精确动作”，需要更紧的头—臂协调和视角稳定的动作解码。
      • 记忆只到物体级（位置和外观），分不清抽屉开/关这类有意义的状态变化，限制多阶段任务；可以给空间 token 加阶段转换信号。
      • 扩展到移动操作或房间尺度需要分层记忆和回环/SLAM 对齐来控制漂移。
      • 持久记忆带来安全和隐私风险：陈旧或错误的记忆可能危及人机共处环境的安全；建议置信度评分、重扫触发、记忆过期、本地存储和人在回路确认。

      我们读出来的

      • 疑点真机每任务 20 个回合，没有方差或置信区间；三个可动头部基线之间、以及 SOMA 与它们之间的很多差距只有 1–3 个回合。
      • 疑点表 2 的三列变体数字与“20 回合 × 阶段平均”的粒度不符；表 13 的 VGGT 配置 27.3 与 Full SOMA 28.3 不一致。
      • 疑点行为指标：First-Fixation Time 的定义与正文解读不符；Time-to-Grasp 定义为步数却以秒报告；失败回合如何计入未说明；任务 2 的搜索转角含义不明；五项降幅在同一任务上异常一致。

      记忆类 harness 里，唯一存“空间状态”的一篇

      在 Harness for Robotics 专题里，SOMA 属于 Persistent State / Memory：它改的是策略记住什么。具体说，它在多步任务中持续保存的是空间状态（每个物体的外观和 3D 位置），形式是一组物体 token，插在 VLM 与 DiT 动作头之间，用交叉注意力读出。它也是同类四篇里唯一和“看什么”深度耦合的：记忆的内容取决于一次主动扫描。

      SOMAMemoryVLAOptimusVLAHiMe
      记住什么每个物体的 DINOv3 外观 + VGGT 3D 框（空间状态）过去各时间步的 VLM 感知 token（256 个）和认知 token（1 个），带时间步位置编码（执行历史）GPM：离线示范库里的整条轨迹；LCM：上一个动作块和 Mamba 隐状态（动作历史）多模态键值库（图像 + 文字：物体状态、空间约束、人的偏好）+ 子目标清单（任务状态）
      按什么索引物体（类别 + 外观 + 几何）时间步任务嵌入的余弦相似度文本键的向量检索
      写入 / 更新扫描时同类关联、平均合并；操作中 α = g·s 的门控 EMA，未匹配的观测追加每步写入门控融合后的 token；超过容量时合并相邻最相似的一对GPM 训练后固定；LCM 每块滚动Sentry 判定子任务完成或偏离时，触发 GPT-4o Planner 做 Add / Update / Delete

      训练在 GR00T N1.5 上微调；感知模型冻结、离线预处理7B Prismatic VLM（OXE 预训练）+ 扩散动作专家，端到端基于 π0.5，三阶段：预训练 → InfoNCE 训 Prior Head → 冻结 GPM 训 LCM只微调执行器（π0.5）；Sentry（Qwen3-VL-8B）和 Planner（GPT-4o）零样本或少样本使用
      • 和 MemoryVLA：结构上最像。两者都用交叉注意力从记忆读、都有一个 sigmoid 门决定新旧比例（MemoryVLA 是 g ⊙ H + (1−g) ⊙ x 融合读出结果，SOMA 是 α = g·s 的 EMA 更新记忆本身）。根本区别在索引：MemoryVLA 按时间存，解决“动作做没做过”（如按钮按前按后看起来一样）；SOMA 按物体和 3D 位置存，解决“东西在哪”。MemoryVLA 用固定第三人称相机，SOMA 靠可动头部把视锥外的东西写进来。SOMA 在相关工作里把 MemoryVLA 归为“存最近观测或关键帧、服务短时推理”。
      • 和 OptimusVLA：记忆放在完全不同的地方。OptimusVLA 记的是动作（相似任务的轨迹、刚执行的动作块），用来改动作生成的起点和平滑性；SOMA 记的是场景。两者可以叠加，互不冲突。
      • 和 HiMe：HiMe 的记忆在策略外面，由大模型用自然语言管理，有显式的增删改，还能记“这是 Alice 的杯子”这类像素里没有的信息；SOMA 的记忆是策略内部的向量，没有删除，也不懂语义状态。HiMe 的频率分层（执行器快、Planner 只在关键节点调用）和 SOMA 的“一次扫描 + 每步刷新”是两种摊销开销的思路。
      • 跨类：和 ActiveVLA。同样针对“看不全”，ActiveVLA 属于 Context Architecture：用标定相机重建点云，在关键区域周围渲染虚拟视角并做 3D 放大，每一步重新决定看什么，不跨步保存。SOMA 移动真实的头部，并把看到的存下来。
      • 跨类：和 RA-VLA。两者都把检索结果通过注意力注入动作生成，但 RA-VLA 检索的是专家示范片段（“怎么做”），来源是回合外的示范库；SOMA 检索的是本回合的场景记忆（“东西在哪”）。
      • 跨类：和 TIC-VLA。TIC-VLA 把 VLM 语义的“陈旧程度”（延迟、期间的自运动）显式交给策略。SOMA 的记忆条目不带任何时间信息，很久以前看到、之后再没被确认过的条目，和刚刷新过的条目在策略眼里没有区别；解读这正是 SOMA 局限里提到的“记忆过期”问题可以借鉴的方向。
      • 和（3）结构化执行、（4）评估与反馈两类：SOMA 在局限里承认记忆只到物体级，分不清抽屉开 / 关这类阶段变化（仿真失败里占 24%）；τ₀-VLA 的文字执行记忆记的正是阶段（标注时压缩已完成的阶段、保留当前子任务细节，例如「已放好杯子」「已加盐」）。解读两者互补，一个回答「东西在哪」，一个回答「做到哪一步」。MotorMind 回答「东西在哪」的办法是每次需要时让 VLM 在多个固定相机视角上画框、三角化，近距离换腕部相机细化；它的失败分析里，VLM 决策错误最多的一类就是定位。
