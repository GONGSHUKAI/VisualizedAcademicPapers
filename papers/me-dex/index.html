ME-Dex 1.0

Bringing Heterogeneous Tactile Sensing into World Action Modeling

把触觉当作和视频一样需要预测的未来观测，而不只是喂给模型的条件。视频、触觉、动作各有一个专家，在世界动作模型里一起从噪声去噪，动作专家在中间层读取“未来画面”和“未来接触”的表示。

做了什么

在视频+动作的世界动作模型（WAM）里加第三路触觉专家，训练时同时预测未来视频、未来触觉潜变量和动作块，三路用 flow matching 联合去噪，只在中间层（H-Bridge）共享注意力。

怎么统一异构触觉

Canonical Hand Model 把夹爪和灵巧手的传感面对齐到一只“规范手”的指区和掌区；Unified Tactile Autoencoder 把各种力场压成顺序固定的区域 token。

结果

RoboTwin 50 任务 91.56 / 91.92（Clean / Random），比 Fast-WAM 高约 2.3–2.7 点；DexJoCo 平均 65.3（DECO.p 57.8）；ManiFeel 平均 70.0（官方 Diffusion Policy 55.0）。

最该留意的

RoboTwin 上推理时把当前触觉置零，成功率几乎不变（91.70 / 91.74）。触觉的作用主要在训练期的预测监督，增益只有 1–3 点且是单种子；DexJoCo 和 ManiFeel 没有去掉触觉的消融；真机只有定性展示。

问题

触觉只当条件输入，缺了什么

把触觉接进机器人策略，最常见的做法是把当前触觉编码后当条件：在 VLA 里拼进前缀 token，在 WAM 里挂到动作专家旁边（下图 a、b 的虚线 “condition”）。这样做简单，但模型从来不需要回答一个问题：接下来接触会怎么变。

论文的核心主张是：触觉和视频一样，都是对“不断演化的世界状态”的观测，所以应该和视频一起作为未来观测来预测。WAM 已经表明，让模型预测未来画面有助于动作生成；ME-Dex 把同样的逻辑推到触觉上，让模型预测未来接触的演化，动作专家再通过共享注意力读到这部分表示。

要把这件事做成，作者列了三个缺口，每个缺口对应一个组件：

数据缺口RoboTwin、DexJoCo 没有原生触觉；HATO、ManiFeel 的触觉数据规模有限、格式各异；采集同步的触觉+动作数据成本高。Agentic Tactile Data Engine：在仿真里回放轨迹，用力传感器直接记录触觉。
表示缺口不同传感器、不同本体（夹爪 / 灵巧手）的触觉布局各不相同，没有共享表示就没法放在一起训练。Canonical Hand Model + Unified Tactile AE：统一空间参照，统一潜空间。
模型缺口怎样在一个预测架构里同时学未来视频、未来触觉和动作，并让动作生成用得上未来触觉的表示。三专家 MoT + H-Bridge：三路 flow matching 联合去噪，中间层共享注意力。

解读这套论证和“WAM 为什么比 VLA 好”是同一条

核心是更密的未来监督能塑造更好的表示。要检验它，得看两件事：去掉“预测未来触觉”会掉多少分；推理时触觉输入到底被用了多少。结果部分会看到，在 RoboTwin 上这两个答案都偏小。另外，朴素地把触觉当条件并不是白给的：π0.5+Tac 在 RoboTwin Random 上比 π0.5 低 3.08 点，在 DexJoCo 平均低 6.5 点（36.7 → 30.2）。

方法 · 全局

一张图看全局

形式化（论文 §3.2）。在时刻 t，模型拿到任务指令 ℓ、当前图像 It（作为视频首帧）、本体状态 st 和当前触觉 Tt，编码后组成条件：

Ct = ( ℓ, st, ztvis, zttac )(1)

要生成的是同一物理时间窗里的三样东西：动作块 A+ = (at, …, at+k−1)、未来视频潜变量 Zvis,+、未来触觉潜变量 Ztac,+。模型学的是它们的联合分布，策略是这个联合分布对动作的边缘：

πθ(A+ | Ct) = ∫ pθ(A+, Zvis,+, Ztac,+ | Ct) dZvis,+ dZtac,+(3)(4)

实现上不做积分：三样东西一起采样，只保留动作。未来视频和未来触觉的真值只在训练时作为目标出现，推理时拿不到。

让动作真正“依赖”未来观测的是式 (5)：在 H-Bridge 层 j ∈ 𝓑，动作侧的更新同时读取视频和触觉的隐状态。

Hj+1act = 𝓕jact( Hjact, Hjvis, Hjtac ),   j ∈ 𝓑(5)

方法 · 统一触觉表示

先对齐到一只“规范手”，再压成区域 token

触觉输入长什么样

每个传感面 r 给出一个力场 Ft(r) ∈ ℝ3×H×W：一个法向分量加两个切向分量，定义在 H×W 网格上。布局掩码标出哪些网格点是有效传感位置（包括当下没有接触的位置）。预处理依次是平滑死区、逐通道 asinh 压缩、归一化、裁剪，最后法向落在 [0, 1]，切向落在 [−1, 1]。页首的动画就是这种数据的样子。

Canonical Hand Model

以人手为模板，为左右手各定义手指区和手掌区，把夹爪和灵巧手看成这个模板的“形态变体”。区域分配只提供共同的空间参照，不要求各末端执行器的表面几何一致。

  • 灵巧手：每个传感面分到它所在的手指或手掌区。
  • RoboTwin 夹爪：两个传感面分别映射到拇指区和食指区，每个面再切成 4 个互不重叠、有顺序的 patch。
  • 不同来源只覆盖模板的不同子集。区域掩码把“这个本体根本没有这块传感器”和“有传感器但此刻没接触”区分开，论文特意强调要保住这个区别。

Unified Tactile Autoencoder

区域分配解决了空间对应，但各来源的力场在分辨率、表面几何、覆盖范围上仍然不同。要让一个触觉预测器通吃，需要一个紧凑、空间组织一致、又保留局部力模式和接触变化的潜空间。这就是 AE 的任务，它在触觉这一路扮演视频 VAE 的角色。

编码器 · 确定性，传感面间共享参数，逐帧

  1. 残差卷积网络提取局部力特征 Surface CNN
  2. 窗口 + 移位窗口注意力，在每个传感面内部 Surface Swin Attention
  3. 带掩码的可学习池化，只在有效传感位置上汇聚。夹爪面在 4 个 patch 内分别池化，灵巧手面整面池化 Region Learned Pooling
  4. token 放进规范槽位，加上区域嵌入和池化类型嵌入；2 层带掩码 Transformer 在同一帧的有效区域之间交换信息。未观测区域保持掩码、输出为 0 Masked Region Attention
→ zttac ∈ ℝN×d，N 个区域 token

解码器 · 从区域 token 还原力场

  1. 收集属于每个传感面的 token，用局部网格位置作 query 做 cross-attention
  2. 残差 MLP + 卷积细化，恢复传感面特征
  3. 力头预测法向和切向分量，接触头预测接触概率
  4. 重建力场 = 力预测 × 接触概率 × 有效位置掩码（后两者沿力通道广播）
→ F̂ ∈ ℝ3×H×W，每个传感面一张
𝓛AE = 𝓛force + 𝓛contact + 𝓛change + λlat 𝓛latent(6)
𝓛_forceSmooth L1。接触位置监督门控之前的力预测，背景位置监督门控之后的重建。
𝓛_contact平衡二元交叉熵，软标签来自死区处理之前的力幅值。
𝓛_change相邻帧的力差要对得上，接触开始和松开的位置权重更大。
𝓛_latent让“有效但没接触”区域的池化特征靠近同一布局下全零输入得到的特征，给“没接触”一个一致的潜空间参照。

AE 在多源触觉上单独预训练，之后冻结，给联合模型提供三样东西：当前触觉条件、未来触觉目标、把预测潜变量还原成力场的解码器。冻结是为了防止在各基准上训练策略时触觉表示漂移。

方法 · World Action Tactile Model

三个专家，只在中间层交换信息

H-Bridge 共享注意力。借鉴 H-Bridge（CVPR 2026）：跨模态交互只放在中间一组层 𝓑。在这些层里，各专家把特征投影到兼容的注意力维度，在视频、触觉、动作全部 token 上做联合自注意力，再映射回各自的宽度；浅层和深层各算各的。论文给的理由有三条：信息交换集中在网络中段；输入端和输出端保留模态专属的处理；需要跨模态注意力的层更少。

表 1 里的 VA、Tac Cond.、Full Joint 三个变体用的是“每一层都联合注意力”；只在中间层联合之后（完整模型），Clean +2.20、Random +1.32。这是整个消融链里 Clean 上最大的一步。

未披露论文没给的架构细节

𝓑 具体是哪几层（图 2 只标了 ×N / ×L / ×N；按每个专家 30 层推算应有 2N + L = 30 解读）；动作块长度 k；未来触觉帧数 T；区域 token 数 N 和宽度 d；注意力有没有时间因果掩码；去噪步数；推理延迟和控制频率；训练算力。

方法 · 联合训练与推理

一套 flow matching，三个噪声水平

xσmm = (1 − σm) x0m + σm εm,    um = εm − x0m,   m ∈ {vis, tac, act}(9)
𝓛joint = λvis 𝓛FMvis + λtac 𝓛FMtac + λact 𝓛FMact(11)

训练。三个干净目标分别是 Zvis,+、Ztac,+、A+。每个模态独立采样噪声水平 σm ∈ [0, 1] 和高斯噪声；首帧、本体状态、当前触觉帧始终保持干净，作为条件。专家在 H-Bridge 层交换特征，同时预测各自的速度。视频和动作用 MSE；触觉用加权平方误差，强调真值触觉潜变量里发生变化的部分。

推理。未来视频潜变量、未来触觉潜变量、动作三路都从高斯噪声出发，在固定的观测条件 Ct 下，用预测的速度一起从噪声水平 1 走到 0；每一步 H-Bridge 都在交换三路正在演化的表示。最后取出动作块去执行。视频和触觉潜变量可以用冻结的解码器还原成画面和力场，但不参与控制。

解读独立噪声水平的意义

训练时每个模态独立采样 σ，和 UWM（论文引用 [8]）这类统一视频-动作扩散模型同类：同一个网络见过各种“谁干净、谁嘈杂”的组合。理论上这能支持“给定动作预测未来触觉”之类的条件查询，但 ME-Dex 只用了三路同步去噪这一种推理方式，其他查询没有评测。

方法 · 数据

Agentic Tactile Data Engine

用途是在仿真中回放和生成动作，给原本没有触觉的数据集补上触觉。论文对它的描述只有一段，流程如下：

已有示范RoboTwin、DexJoCo 的视觉 + 动作，没有触觉
→
仿真中回放动作让仿真里的力传感器在回放过程中直接记录触觉
→
补齐触觉的轨迹触觉与原有视觉、动作对齐
生成新轨迹生成并执行新的动作轨迹
→
同样记录得到额外的触觉数据
→
额外配对数据视觉 + 触觉 + 动作
输出在共享时间窗上配对的触觉、视觉、动作：既提供当前观测条件，也提供对齐的未来目标，直接用于联合训练。补录后的训练集：RoboTwin 50 任务 27,500 条 Clean + Random 轨迹；DexJoCo 1,100 条示范。

疑点“Agentic” 指什么没有说清

没有说明 agent 具体负责什么（生成轨迹？筛选？调度？）、新轨迹怎样生成、失败轨迹怎样处理、生成了多少条；也没有说明仿真里力传感器的模型，以及切向力是怎样得到的。

定性结果

读懂它

这些数字真正说明了什么

1. 触觉主要在训练时起作用，不在推理时

RoboTwin 上把当前触觉输入置零：91.70 / 91.74，完整模型是 91.56 / 91.92。论文自己的措辞是“对当前触觉输入的敏感度有限”。Clean-only 实验更是全程触觉置零评测。

所以要问的不是“触觉反馈有没有用”，而是“把未来触觉当预测目标，能不能让表示更好”。

2. “预测未来触觉”这一步本身只贡献约 0.3–1 点

Full Joint 对比 Tac Cond.：Clean +0.32，Random +1.06。Clean 上最大的一步来自 H-Bridge（+2.20），Random 上最大的一步来自加当前触觉条件（+2.64）。

单种子，评测次数未写；差距在这个量级时，结论需要多种子确认。

3. 绝对水平主要来自 WAM 骨干

完全不用触觉的 ME-Dex (VA) 已有 88.74 / 86.90，和 Motus 88.66 / 87.02、Fast-WAM 89.22 在同一档；π0.5 只有 52.76 / 60.74。视频和动作专家都从 Motus 预训练权重初始化。

VA 之上的全部改动（触觉条件、触觉预测、H-Bridge）合计 +2.82 / +5.02 点。

4. 朴素地把触觉当条件，可能反而有害

π0.5+Tac 在 RoboTwin Random 上 −3.08，在 DexJoCo 平均从 36.7 降到 30.2（Hammer Nail 40 → 10、Pick Bucket 82 → 46）。Fast-WAM 加触觉则 +1.00。

同一个 AE 编码的触觉，接在不同骨干上效果相反。这是本文“别只当条件”论点里最直接的反面证据。

容易误解的地方

  • “真机评测证明性能提升”。摘要写“together with real robot evaluations, demonstrate improved manipulation performance”，但正文的真机部分是定性评估，只有图 7 的 rollout，没有成功率，也没有和任何基线对比。
  • “触觉让 ME-Dex 在 DexJoCo 和 ManiFeel 上领先”。这两个基准上没有 ME-Dex 不用触觉的变体，领先可能来自 5B 级 WAM 骨干和 Motus 预训练，无法归因到触觉。ManiFeel 的基线是一个 Diffusion Policy，两者规模差距很大。
  • “Clean-only 实验超过排行榜第一”。基线数字来自 RoboTwin 排行榜，训练协议未必一致；而且 ME-Dex 用了 Motus 预训练。
  • “表 5 证明仿真触觉可信”。表 5 只是 AE 的重建精度，衡量的是 AE 能否复现仿真信号，不是仿真信号像不像真实传感器。
  • “推理时只输出动作”。推理时三路一起去噪，每个动作块都要把未来视频也生成一遍（视频专家是 Wan2.2-5B 结构）；只是最后只拿动作去执行。

FAQ

预测未来触觉到底带来了什么？

论文唯一直接的证据是 RoboTwin 表 1 的 Full Joint 对 Tac Cond.：Clean +0.32、Random +1.06（单种子）。在此基础上换成 H-Bridge 再加 +2.20 / +1.32，但这一步改的是注意力结构，不是触觉。

DexJoCo 和 ManiFeel 上没有“去掉触觉预测”的消融。论文也没有报告未来触觉预测本身准不准：表 5 是 AE 的重建，不是模型对未来的预测。

解读论文的机制解释是“未来触觉监督塑造了与动作专家交换的表示”（式 5），这是合理的假设，但文中没有表示层面的分析来支撑。

仿真里回放记录的力信号可信吗？

论文只说触觉是“在仿真回放时由力传感器直接记录”，没有给传感器模型、噪声设置，也没有和真实传感器做对比。表 5 衡量的是 AE 能否重建这些信号，不衡量信号本身是否真实。

RoboTwin 和 DexJoCo 的全部触觉数据都来自这个途径，而真机只有定性展示。所以“仿真触觉学到的东西能不能迁移到真实触觉”，目前没有证据。

推理时把触觉置零都不掉点，那触觉还有用吗？

在 RoboTwin 上，当前触觉输入的作用可以忽略，论文自己也承认。若说触觉有用，作用在训练阶段：把未来触觉当预测目标。置零变体仍然保留训练时的触觉监督，推理时也仍在预测未来触觉。

解读RoboTwin 以夹爪抓放为主，接触状态多半能从画面推断出来。要检验触觉反馈的价值，需要真正依赖触觉的测试，比如遮挡、透明或易滑物体、有力度要求的指令，论文没有做。论文在局限里也写了：目前触觉只通过动作块之间的观测更新和重规划起作用。

为什么要 Canonical Hand，而不是每种传感器一个编码器？

为了让一个 AE 和一个触觉专家通吃所有来源，各来源的 token 要有一致的空间含义和顺序。模板让“食指上的压力”在夹爪和灵巧手上落到同一个槽位；区域掩码区分“没有这块传感器”和“有但没接触”。

解读论文里只有 AE 是跨来源共享训练的，策略在每个基准上各自训练。所以“跨本体共享触觉表示能带来迁移”这一点还没有实验检验，比如在 RoboTwin 触觉上预训练对 DexJoCo 有没有帮助。

推理成本多大？

论文没有报告延迟、去噪步数或控制频率。

解读每个动作块都要把 Wan2.2-5B 结构的视频专家连同另外两路一起去噪，代价不低。论文引用的 Fast-WAM 研究的正是“推理时不生成视频还行不行”；ME-Dex 没有测试省掉视频的推理变体。

局限与疑点

作者承认的，和我们读出来的

论文第 5 节自述

  • 统一触觉编码器的预训练受限于数据规模和传感器多样性。计划扩展到更多传感布局和接触模式，并系统评估对未见配置的泛化。
  • 目前策略主要通过观测更新和动作块之间的重规划来使用触觉反馈。计划探索触觉驱动的局部高频反馈控制，在执行中调整联合预测出的动作。

解读我们的疑点

  • 仿真触觉的真实度：RoboTwin / DexJoCo 的触觉全部来自仿真回放，没有与真实传感器的对比，也没有 sim-to-real 实验。
  • 真机规模：只有两个定性任务，没有成功率、试验次数和训练数据量。
  • 统计强度：单种子；RoboTwin 和 DexJoCo 的评测次数未写；RoboTwin 上的关键差距只有 0.3–2.7 点。
  • 基线公平性：表 1 里自训的 π0.5 在 Clean 上只有 52.76，而表 2 排行榜上只用 Clean 数据训练的 π0.5 是 70.7，自训基线可能欠调；表 2 与排行榜的训练协议未必一致；DECO 数字来自官方发布；ManiFeel 对比的是规模小得多的 Diffusion Policy。
  • 归因缺口：DexJoCo 和 ManiFeel 没有去掉触觉的消融；也没有“有 Motus 预训练、没触觉”的对照。
  • 一个小异常：Fast-WAM 与 Fast-WAM+Tac 的 Clean、Random 数字完全相同（89.22 / 89.22、90.22 / 90.22），论文没有解释。
  • 细节缺失：k、T、N、d、H-Bridge 层位置、λ 系数、去噪步数、算力、推理延迟都没给；数据引擎只有一段描述。
  • 未评测未来触觉预测的质量：模型声称在预测未来接触，但没有任何指标衡量这些预测对不对。

ME-Dex 和 Motus2：同一条世界模型路线，触觉放在两个不同的位置

两者渊源很近：ME-Dex 的视频和动作专家从 Motus（第一代）的权重初始化，Motus2 是同一清华团队的下一代，ME-Dex 的相关工作一节也专门提到了 Motus2。但两者给触觉的角色几乎相反：

ME-Dex 1.0 · 触觉是“重”的观测模态

30 层、宽 512 的完整触觉专家，未来触觉以 N 个空间区域 token × T 帧的形式和视频一起联合去噪，推理时也生成。触觉只在动作块之间通过新观测起作用，高频反馈留作未来工作。

证据：仿真上 VA → 完整模型 +2.8 / +5.0 点（含 H-Bridge）；真机无数字。

Motus2 · 触觉是“轻”的快速修正通道

30 层、宽 128 的轻量触觉专家。主干把 48 步动作块只去噪到 σc = 0.2，然后切成 8 个 6 步子块（30 Hz 下各 0.2 s），每个子块执行前用最新触觉窗口完成 σc → 0。未来力预测只在训练时用；精修动作的 token 看不到加噪的未来力 token。

证据：真机两任务（各 20 次）60.0% → 72.5%。

解读两条路线可以互补

ME-Dex 的局限一节写的“触觉驱动的局部高频反馈控制”，正是 Motus2 已经实现的做法；反过来，Motus2 局限一节说触觉手套数据难以跨本体迁移，而跨本体统一表示正是 ME-Dex 的 Canonical Hand + 统一 AE 想解决的。ME-Dex 在 RoboTwin 上“推理时置零触觉不掉点”的结果也说明：只在块间读触觉，反馈价值很难体现；要让触觉在执行中起作用，块内的快速修正通道可能是必要的。
